**Покрывает листья** (ветка «Операционные системы / Основы Windows / Службы Windows»):
- Диспетчер служб (SCM) и типы запуска
- Зависимости служб и политики восстановления
- Типовые службы Windows и точки мониторинга для L1

**Сценарий.** ООО «СтройИнвест-Урал», SOC на аутсорсе. 14 марта 2026, 02:40. EDR на хосте бухгалтерии `BUH-WS07` поднял алерт «New service was installed». Аналитик дежурной смены L1 запросил у инженера выгрузку конфигурации всех служб хоста (`sc query state= all`, затем `sc qc` по каждому имени) и должен найти подозрительную службу и снять её атрибуты.

**Исходные данные.** Файл `services-scqc-discovery.txt` — 18 служб в формате `sc qc`. Ключевые фрагменты:

```
[SC] QueryServiceConfig SUCCESS

SERVICE_NAME: Dnscache
        TYPE               : 20  WIN32_SHARE_PROCESS
        START_TYPE         : 2   AUTO_START
        BINARY_PATH_NAME   : C:\Windows\System32\svchost.exe -k NetworkService -p
        DISPLAY_NAME       : DNS Client
        SERVICE_START_NAME : NT AUTHORITY\NetworkService

[SC] QueryServiceConfig SUCCESS

SERVICE_NAME: Spooler
        TYPE               : 10  WIN32_OWN_PROCESS
        START_TYPE         : 2   AUTO_START
        BINARY_PATH_NAME   : C:\Windows\System32\spoolsv.exe
        DISPLAY_NAME       : Print Spooler
        SERVICE_START_NAME : LocalSystem

[SC] QueryServiceConfig SUCCESS

SERVICE_NAME: WinTelemetrySvc
        TYPE               : 10  WIN32_OWN_PROCESS
        START_TYPE         : 2   AUTO_START
        BINARY_PATH_NAME   : C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe -NoProfile -WindowStyle Hidden -EncodedCommand JABjACAAPQAgAE4AZQB3AC0ATwBiAGoAZQBjAHQAIABOAGUAdAAuAFcAZQBiAEMAbABpAGUAbgB0AA==
        DISPLAY_NAME       : Windows Telemetry Service
        SERVICE_START_NAME : LocalSystem
```

**Задача.** Найти в выгрузке службу, не относящуюся к штатным службам Windows, и снять её атрибуты.

**Решение по шагам.**

**Шаг 1 — понять, что именно читаем.** В каждом блоке `sc qc` главное для триажа — `BINARY_PATH_NAME` (что служба запускает) и `SERVICE_START_NAME` (под какой учётной записью). Штатные службы запускаются из `C:\Windows\System32` (обычно `svchost.exe -k <группа>`, либо собственный системный бинарь вроде `spoolsv.exe`).

**Контрольный вопрос 1.1.** В каком поле выгрузки видно, какой исполняемый файл запускает служба? **Ответ:** `BINARY_PATH_NAME`

**Шаг 2 — пройти по бинарям и найти выпадающий из ряда.** Почти все службы указывают `svchost.exe -k …` или системный бинарь в `System32`. Одна служба запускает `powershell.exe` с ключом `-EncodedCommand` и скрытым окном — штатная служба так не делает: служба, исполняющая кодированный PowerShell, это признак закрепления.

**Контрольный вопрос 1.2.** Имя этой службы? **Ответ:** `WinTelemetrySvc`

**Контрольный вопрос 1.3.** Какой исполняемый процесс она запускает? **Ответ:** `powershell.exe`

**Шаг 3 — оценить опасность по типу запуска и правам.** У службы `START_TYPE = AUTO_START` (стартует вместе с системой, не требует входа пользователя) и `SERVICE_START_NAME = LocalSystem` (права уровня SYSTEM). Это закрепление с максимальными правами, выполняющееся при каждой загрузке.

**Контрольный вопрос 1.4.** Тип запуска службы? **Ответ:** `AUTO_START`

**Контрольный вопрос 1.5.** Под какой учётной записью запускается служба? **Ответ:** `LocalSystem`

**Шаг 4 — вердикт.** True Positive: закрепление через службу Windows. Имя `WinTelemetrySvc` и отображаемое имя «Windows Telemetry Service» маскируются под штатную телеметрию, но штатной службы с таким именем нет. Снять атрибуты в тикет, эскалировать на L2.

**Готовый результат.** В тикет: служба `WinTelemetrySvc`, бинарь `powershell.exe -EncodedCommand …`, тип `AUTO_START`, учётка `LocalSystem`, вердикт TP — закрепление через службу.

**Ключевые уроки.**
- Служба — это механизм автозапуска; `START_TYPE` показывает, когда она стартует, `BINARY_PATH_NAME` — что запускает, `SERVICE_START_NAME` — с какими правами.
- Служба, запускающая интерпретатор (`powershell.exe`, `cmd.exe`, `rundll32.exe`) с аргументами, особенно `-EncodedCommand`/`-enc`, — сильный признак вредоносной.
- Сочетание `AUTO_START` + `LocalSystem` означает запуск с правами SYSTEM при каждой загрузке — максимальная опасность.
- Не каждый путь вне `System32` вреден: Microsoft Defender (`MsMpEng.exe`) штатно лежит в `C:\ProgramData\Microsoft\Windows Defender\…`. Смотреть на совокупность признаков, а не на один путь.
