**Покрывает листья** (ветка «Операционные системы / Основы Windows / Аутентификация NTLM»):
- Схема NTLM и хранение хэшей
- Сравнение с Kerberos в доменной среде
- Риски для SOC: ретрансляция и кража учётных данных

**Сценарий.** Торговая сеть «Берёзка-Ритейл», 20 марта 2026, 11:30. После алерта о попытке ретрансляции учётных данных аналитик L1 проверяет, разрешает ли кассовый ПК `KASSA-12` слабый NTLM. Снят экспорт ветки `Lsa`.

**Исходные данные.** Файл `ntlm-lsa-discovery.reg`:

```
[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Lsa]
"LmCompatibilityLevel"=dword:00000001
"NoLMHash"=dword:00000001
"RestrictAnonymous"=dword:00000001
"RestrictAnonymousSAM"=dword:00000001
"EveryoneIncludesAnonymous"=dword:00000000

[HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0]
"NtlmMinClientSec"=dword:20080000
"NtlmMinServerSec"=dword:20080000
"RestrictSendingNTLMTraffic"=dword:00000002
"RestrictReceivingNTLMTraffic"=dword:00000002
"AuditReceivingNTLMTraffic"=dword:00000002
```

**Задача.** Снять значения ключевых параметров NTLM и найти единственный, выставленный в небезопасное значение.

**Решение по шагам.**

**Шаг 1 — перевести значения в десятичный вид.** `dword:00000001` = 1, `dword:00000002` = 2, `dword:00000005` = 5. Снимаем значения интересующих параметров.

**Контрольный вопрос 1.1.** Какое значение у `LmCompatibilityLevel` десятичным числом? **Ответ:** `1`

**Контрольный вопрос 1.2.** Какое значение у `NoLMHash`? **Ответ:** `1`

**Контрольный вопрос 1.3.** Какое значение у `RestrictSendingNTLMTraffic`? **Ответ:** `2`

**Шаг 2 — сверить с безопасным эталоном.** Безопасно: `LmCompatibilityLevel = 5`, `NoLMHash = 1`, `RestrictSendingNTLMTraffic = 2`, `AuditReceivingNTLMTraffic = 2`. Здесь `NoLMHash`, `RestrictSendingNTLMTraffic` и аудит в норме, а `LmCompatibilityLevel = 1` — допускает LM и NTLMv1, то есть слабые ответы, пригодные для ретрансляции и взлома.

**Контрольный вопрос 1.4.** Какой параметр настроен небезопасно? **Ответ:** `LmCompatibilityLevel`

**Контрольный вопрос 1.5.** Какое значение у `AuditReceivingNTLMTraffic`? **Ответ:** `2`

**Вердикт.** Хост допускает слабый NTLM (`LmCompatibilityLevel = 1`) — повышенный риск ретрансляции/кражи учётных данных. Зафиксировать в тикет, рекомендовать поднять уровень до 5; алерт о ретрансляции рассматривать с этим контекстом.

**Готовый результат.** В тикет: `LmCompatibilityLevel = 1` (небезопасно, эталон 5), остальные параметры NTLM в норме, хост уязвим к слабому NTLM.

**Ключевые уроки.**
- NTLM слабее Kerberos; LM и NTLMv1 поддаются ретрансляции и взлому.
- `LmCompatibilityLevel`: `5` — только NTLMv2 (безопасно), `≤ 2` — допускает LM/NTLMv1 (слабо).
- `NoLMHash = 1` запрещает хранение слабого LM-хэша; `0` — хранит (риск кражи).
- `RestrictSendingNTLMTraffic = 2` запрещает исходящий NTLM; `AuditReceivingNTLMTraffic = 2` включает аудит — без него попытки NTLM не попадут в SOC.
- Значения `.reg` шестнадцатеричные: `dword:00000005` = 5.
