- Системные процессы: lsass, csrss, winlogon — функции и приметы аномалий

**Сценарий.** Торговая сеть «Берёзка-Ритейл», 19 марта 2026, 13:20. На кассовом ПК `KASSA-12` EDR отметил процесс, обращающийся к памяти `lsass`. Аналитик L1 снял список процессов (`tasklist /v /fo list`) и должен найти процесс-самозванец.

**Исходные данные.** Файл `tasklist-v-discovery.txt`. Фрагменты (настоящий `svchost`, настоящий `lsass` и выпадающий процесс):

```
Image Name:   lsass.exe
PID:          724
Session Name: Services
Session#:     0
User Name:    NT AUTHORITY\SYSTEM
Window Title: N/A

Image Name:   svchost.exe
PID:          836
Session Name: Services
Session#:     0
User Name:    NT AUTHORITY\SYSTEM
Window Title: N/A

Image Name:   svhost.exe
PID:          5012
Session Name: Console
Session#:     1
User Name:    KASSA-12\jsmith
Window Title: N/A
```

**Задача.** Найти в списке процесс, маскирующийся под системный, и снять его идентификаторы.

**Решение по шагам.**

**Шаг 1 — знать «лицо» системных процессов.** Настоящие `svchost.exe`, `lsass.exe`, `services.exe` работают в сессии 0 (`Session# 0`, `Session Name: Services`) под `SYSTEM`/`LOCAL SERVICE`/`NETWORK SERVICE`. Пользовательские процессы (`explorer.exe`, `msedge.exe`) — в сессии 1 под `HOST\пользователь`.

**Контрольный вопрос 1.1.** Под какой учётной записью работает настоящий `svchost.exe`? **Ответ:** `SYSTEM` (либо `LOCAL SERVICE` / `NETWORK SERVICE`)

**Шаг 2 — найти выпадающий.** Среди процессов есть `svhost.exe` (без буквы «c») — это не `svchost.exe`, а имя-опечатка. Вдобавок он работает в сессии 1 под `KASSA-12\jsmith`, где системного процесса быть не должно.

**Контрольный вопрос 1.2.** Какой процесс выдаёт себя за системный? **Ответ:** `svhost.exe`

**Контрольный вопрос 1.3.** Под какой настоящий системный процесс он маскируется? **Ответ:** `svchost.exe`

**Шаг 3 — снять идентификаторы для тикета.**

**Контрольный вопрос 1.4.** PID процесса-самозванца? **Ответ:** `5012`

**Контрольный вопрос 1.5.** Сколько в выгрузке настоящих процессов `svchost.exe`? **Ответ:** `5`

**Вердикт.** True Positive: процесс `svhost.exe` маскируется под `svchost.exe`, работает в пользовательской сессии. Снять PID и имя, эскалировать на L2.

**Готовый результат.** В тикет: самозванец `svhost.exe` PID 5012, сессия 1, `KASSA-12\jsmith`, маскируется под `svchost.exe`, вердикт TP.

**Ключевые уроки.**
- Системные процессы живут в сессии 0 под `SYSTEM`/`LOCAL SERVICE`/`NETWORK SERVICE`; те же имена в сессии 1 под пользователем — аномалия.
- Имя-опечатка (`svhost`, `scvhost`, `lsasss`) — частая маскировка; сверять имя посимвольно с эталоном.
- В норме ровно один `lsass.exe` и один `services.exe`; второй экземпляр — повод для эскалации.
- `tasklist /v` не показывает путь к файлу и родительский процесс — для них нужен отдельный инструмент (разбирается в разделе «Типичные сценарии L1»).
