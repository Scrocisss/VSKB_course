**Покрывает листья** (ветка «Операционные системы / Основы Windows / Планировщик задач Windows»):
- Task Scheduler: триггеры и персистентность через задачи
- Признаки злоупотребления: нетипичные задачи, пути и триггеры
- Журналирование Task Scheduler: Event ID 100/106/200/201 и видимость в SOC

**Сценарий.** Торговая сеть «Берёзка-Ритейл», 19 марта 2026, 21:05. На кассовом ПК `KASSA-12` после инцидента со службой проверяется закрепление через планировщик. Аналитик L1 снял полную выгрузку задач (`schtasks /query /v /fo list`).

**Исходные данные.** Файл `schtasks-v-discovery.txt`. Штатная задача и выпадающая:

```
TaskName:                             \Microsoft\Windows\UpdateOrchestrator\Schedule Scan
Author:                               Microsoft Corporation
Task To Run:                          C:\Windows\System32\usoclient.exe StartScan
Run As User:                          SYSTEM
Schedule Type:                        Daily

TaskName:                             \WindowsUpdateCheck
Author:                               KASSA-12\jsmith
Task To Run:                          powershell.exe -NoProfile -WindowStyle Hidden -EncodedCommand JABzAD0ATgBlAHcALQBPAGIAagBlAGMAdAAg...
Run As User:                          SYSTEM
Schedule Type:                        At logon time
```

**Задача.** Найти задачу, созданную не системой и запускающую подозрительную команду, и снять её атрибуты.

**Решение по шагам.**

**Шаг 1 — отделить штатные задачи.** У штатных задач `Author = Microsoft Corporation` (или производитель), `Task To Run` ведёт в `System32`/`Program Files`. Поле `Author` — быстрый фильтр: задачу, созданную обычным пользователем, нужно рассмотреть.

**Контрольный вопрос 1.1.** Какое поле выгрузки показывает, кто создал задачу? **Ответ:** `Author`

**Шаг 2 — найти выпадающую задачу.** Задача `\WindowsUpdateCheck` создана `KASSA-12\jsmith` (не Microsoft) и запускает `powershell.exe` со скрытым окном и `-EncodedCommand`. Имя маскируется под обновление Windows.

**Контрольный вопрос 1.2.** Какая задача подозрительная? **Ответ:** `\WindowsUpdateCheck`

**Контрольный вопрос 1.3.** Какой процесс она запускает? **Ответ:** `powershell.exe`

**Шаг 3 — оценить триггер и права.** `Schedule Type = At logon time` — задача срабатывает при каждом входе (персистентность), `Run As User = SYSTEM` — с правами системы.

**Контрольный вопрос 1.4.** Какой тип расписания у задачи? **Ответ:** `At logon time`

**Контрольный вопрос 1.5.** Под какой учётной записью выполняется задача? **Ответ:** `SYSTEM`

**Вердикт.** True Positive: закрепление через задачу планировщика, запуск кодированного PowerShell при входе с правами SYSTEM.

**Готовый результат.** В тикет: задача `\WindowsUpdateCheck`, автор `KASSA-12\jsmith`, запускает `powershell.exe -EncodedCommand …`, триггер «при входе», `Run As User SYSTEM`, вердикт TP.

**Ключевые уроки.**
- `Author` штатной задачи — `Microsoft Corporation` или производитель ПО; автор-пользователь у системной по виду задачи — повод для проверки.
- `Task To Run`, запускающий `powershell.exe`/`cmd.exe`/`rundll32.exe` или бинарь из `Public`/`ProgramData`/пользовательской папки, — признак вредоносной задачи.
- Триггеры закрепления: `At logon time`, `At system start up`, частый повтор (`Repeat: Every: 0:10:00`).
- Задача может лежать и под `\Microsoft\Windows\…` — проверять `Author` и `Task To Run`, а не только путь имени.
