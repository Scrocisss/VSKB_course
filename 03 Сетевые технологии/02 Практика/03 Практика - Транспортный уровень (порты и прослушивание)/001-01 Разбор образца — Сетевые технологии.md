**Покрывает листья** (ветка «Сетевые технологии / Уровни TCP/IP / Транспортный уровень»):
- TCP: трёхстороннее рукопожатие, порты и флаги
- UDP: дейтаграммы и сценарии без установки соединения
- Порты: well-known, registered, ephemeral — что отслеживать аналитику

**Сценарий.** Банк «ФинТраст», 22 марта 2026, 18:40. После обнаружения C2-канала на хосте ищут открытый бэкдор-порт. Аналитик L1 снял список прослушиваемых портов с процессами (`netstat -antp`).

**Исходные данные.** Файл `netstat-listen-discovery.txt`:

```
Proto Recv-Q Send-Q Local Address           Foreign Address         State       PID/Program name
tcp        0      0 0.0.0.0:22              0.0.0.0:*               LISTEN      712/sshd
tcp        0      0 0.0.0.0:80              0.0.0.0:*               LISTEN      1230/apache2
tcp        0      0 127.0.0.1:3306          0.0.0.0:*               LISTEN      1450/mariadbd
tcp        0      0 0.0.0.0:9001            0.0.0.0:*               LISTEN      4870/nc
```

**Задача.** Найти нештатный прослушиваемый порт (бэкдор) и снять его атрибуты.

**Решение по шагам.**

**Шаг 1 — сопоставить порты со службами.** Штатно: `22` — `sshd`, `80` — `apache2`, `3306` (на `127.0.0.1`) — `mariadbd`. Каждый порт объясняется своей службой.

**Контрольный вопрос 1.1.** В каком состоянии находятся прослушивающие порты? **Ответ:** `LISTEN`

**Шаг 2 — найти нештатный порт.** Порт `9001` слушает процесс `nc` (netcat) — это не служба, а инструмент, типично используемый как бэкдор-слушатель. Порт `9001` не соответствует ни одной штатной службе.

**Контрольный вопрос 1.2.** На каком порту слушает бэкдор? **Ответ:** `9001`

**Контрольный вопрос 1.3.** Какая программа открыла этот порт? **Ответ:** `nc`

**Контрольный вопрос 1.4.** Какой PID у этого процесса? **Ответ:** `4870`

**Шаг 3 — оценить доступность.** Порт привязан к `0.0.0.0` — слушает на всех интерфейсах, то есть доступен снаружи.

**Контрольный вопрос 1.5.** К какому адресу привязан бэкдор-порт? **Ответ:** `0.0.0.0`

**Вердикт.** True Positive: бэкдор — `nc` (PID 4870) слушает на `0.0.0.0:9001`, доступен извне. Снять порт, PID, программу, эскалировать.

**Готовый результат.** В тикет: бэкдор-listener `0.0.0.0:9001`, программа `nc`, PID 4870, вердикт TP.

**Ключевые уроки.**
- Порты: well-known (`0–1023`), registered (`1024–49151`), ephemeral (`49152+`); службы слушают в состоянии `LISTEN`.
- Listener на необычном порту, привязанный к `0.0.0.0`, открытый `nc`/`python`/`bash`, — бэкдор.
- `PID/Program name` (`netstat -antp`) показывает, какой процесс открыл порт.
- Привязка к `127.0.0.1` — только локально; к `0.0.0.0` — доступно со всех интерфейсов (опаснее).
