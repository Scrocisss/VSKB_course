# VLAN и сегментация сети

## 1. Сегментация и VLAN: обзор концепций и разграничение понятий

**Сегментация сети** — это практика разделения физической или логической инфраструктуры на изолированные зоны, каждая из которых представляет собой отдельную область безопасности. Цель сегментации — ограничить распространение угрозы в случае компрометации: злоумышленник, проникший в одну зону, не может свободно переходить в другие без преодоления дополнительных барьеров. Такая архитектура напрямую противодействует *боковому перемещению* (lateral movement) — ключевому этапу многих целевых атак [OWASP Network Segmentation Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Network_Segmentation_Cheat_Sheet.html).

На практике сегментация реализуется различными механизмами, работающими на разных уровнях модели OSI. Важно различать:

- **Физическую сегментацию** — использование отдельных кабельных систем и коммутаторов для разных групп устройств.  
- **Логическую сегментацию на канальном уровне (L2)** — VLAN (Virtual Local Area Network) по стандарту IEEE 802.1Q.  
- **Логическую сегментацию на сетевом уровне (L3)** — разделение на IP-подсети с применением маршрутизаторов и фильтрующих правил (ACL, файрволов).  
- **Микросегментацию** — изоляцию на уровне отдельных рабочих нагрузок, часто с применением технологий overlay (VXLAN, NSX) и принципов Zero Trust.

В документе Allied Telesis VLAN-сегментация описывается как метод, при котором «порт коммутатора в режиме Access отправляет нетегированные кадры и ассоциируется только с одним VLAN»; это по сути делит один физический коммутатор на несколько независимых “подкоммутаторов” [VLANs Feature Overview and Configuration Guide](https://www.alliedtelesis.com/sites/default/files/vlan_feature_config_guide_revd.pdf).

Нередко понятия «VLAN» и «подсеть» смешивают. Принципиальное различие заключается в том, что VLAN — это широковещательный домен L2, а подсеть — это логическое объединение устройств на L3, определяемое маской подсети. Одна подсеть обычно размещается внутри одного VLAN, но один VLAN может содержать несколько подсетей (хотя это усложняет безопасность и управление).

С точки зрения SOC-аналитика, сегментация сокращает поверхность атаки и упрощает выявление аномалий. Если политика межсегментного взаимодействия определена явно (например, VLAN отдела кадров не должен обмениваться данными с VLAN гостевого Wi-Fi), любое отклонение от разрешённых потоков в логах коммутатора или межсетевого экрана становится индикатором потенциального инцидента.

Для наглядности ключевые виды сегментации сведены в таблицу:

| Вид сегментации | Уровень OSI | Основной механизм | Инструментарий / реализация | Типичные сценарии применения |
|------------------|-------------|-------------------|-----------------------------|------------------------------|
| Физическая | 1 (физический) | Раздельные кабельные системы, изолированные коммутаторы | Отдельные стеки оборудования | Максимальная безопасность, высокие затраты |
| VLAN (802.1Q) | 2 (канальный) | VLAN-теги в заголовке Ethernet, изоляция портов | Управляемые коммутаторы, режимы access/trunk | Офисная сегментация: отделы, гости, серверы |
| IP-подсети + ACL | 3 (сетевой) | Фильтрация по IP-адресам и портам на маршрутизаторах/L3-коммутаторах | ACL, межсетевые экраны, SVI | Ограничение меж-VLAN трафика, управление маршрутизацией |
| Файрвольная сегментация | 3–7 (приложения) | Политики межсетевого экрана с анализом состояния (stateful), Application Layer Gateway | Palo Alto, CheckPoint, iptables, NSG в облаке | Защита периметра, DMZ, проверка трафика между зонами |
| Микросегментация (Zero Trust) | 2–7 | Overlay-сети, тегирование трафика, политики на уровне рабочей нагрузки | VMware NSX, Cisco ACI, сервисные сетки | Изоляция контейнеров, микро-приложений, доступ по идентичности |

Иллюстративная ASCII-схема показывает, как один коммутатор с поддержкой VLAN реализует несколько широковещательных доменов:

```text
[Физический коммутатор]
   │
   ├─ VLAN 10 (HR): порты 1-8   → широковещательный домен A
   ├─ VLAN 20 (Finance): порты 9-16 → широковещательный домен B
   └─ VLAN 30 (IT): порты 17-24    → широковещательный домен C
```

Кадры, отправленные устройством в VLAN 10, никогда не достигнут портов VLAN 20 без участия маршрутизатора (L3). Широковещательные (broadcast) и неизвестные одноадресные (unknown unicast) кадры остаются в пределах своего VLAN.

Таким образом, VLAN — это базовая строительная единица современной сегментации. Их правильное проектирование и разграничение непосредственно влияет на способность SOC-команды обнаруживать и сдерживать атаки на ранних этапах.

## 2. Внутренняя механика VLAN: теги, порты и доменные границы

### 2.1 IEEE 802.1Q — механизм тегирования

Стандарт IEEE 802.1Q определяет метод вставки 4-байтового тега в заголовок Ethernet-кадра между полем MAC-адреса источника и полем EtherType (или длины). Структура тега:

| TPID (2 байта) (Tag Protocol Identifier) | PCP (3 бита) (Priority) | CFI/DEI (1 бит) (Drop Eligible Ind.) |
| --- | --- | --- |
| VID (12 бит) (VLAN Identifier |  |  |

- **TPID** (Tag Protocol Identifier) — всегда 0x8100 для 802.1Q.
- **PCP** (Priority Code Point) — 3-битное поле для качества обслуживания (CoS, Class of Service), значения 0–7.
- **CFI/DEI** — бит индикатора канонического формата (Canonical Format Indicator), в современных стандартах — DEI (Drop Eligible Indicator).
- **VID** — 12-битный идентификатор VLAN, допускает значения от 1 до 4094 (0 и 4095 зарезервированы). Таким образом, максимальное число активных VLAN ограничено 4094 [Habr, «Сложно о простом. Часть 2»](https://habr.com/ru/companies/timeweb/articles/874768).

На приёме коммутатор анализирует VID и принимает решение по таблице VLAN-ассоциаций, построенной на основе конфигурации портов.

### 2.2 Режимы портов и обработка тегов

Порты управляемого коммутатора работают в одном из нескольких режимов, определяющих, как они обрабатывают тегированные кадры.

| Режим порта | Приём (Ingress) | Передача (Egress) | Применение |
|--------------|-----------------|-------------------|------------|
| Access | Ожидает только нетегированные кадры; назначает их в VLAN порта (PVID) | Снимает тег (отправляет нетегированный кадр) | Подключение конечных устройств (ПК, принтеры) |
| Trunk | Принимает как тегированные (если VID разрешён), так и нетегированные (относятся к Native VLAN) | Отправляет тегированные кадры для всех разрешённых VLAN, кроме Native VLAN, для которого кадр идёт без тега | Соединения между коммутаторами, подключение к маршрутизатору |
| Hybrid (проприетарный) | Комбинация Access и Trunk: нетегированные кадры относятся к PVID, тегированные принимаются по списку разрешённых | Для одних VLAN кадры отправляются с тегом, для других — без | Используется в оборудовании некоторых вендоров (например, Huawei) с концепцией «untagged member» |

Параметр **PVID** (Port VLAN ID) определяет, в какой VLAN попадает нетегированный трафик, поступающий на порт. В режиме Access PVID равен единственному VLAN порта. В режиме Trunk PVID соответствует Native VLAN.

Особое значение имеет **Native VLAN** на транковом порту. Все нетегированные кадры, полученные транком, ассоциируются с Native VLAN. По умолчанию на многих коммутаторах Native VLAN = VLAN 1, что создаёт угрозу безопасности: атакующий может отправить специально сформированные кадры, чтобы пробиться из своего VLAN в другой — атака *VLAN hopping*.

### 2.3 Таблица VLAN-коммутации и широковещательные домены

Коммутатор ведёт ассоциативную таблицу MAC-адресов с привязкой к VLAN. Типичная запись содержит: `VLAN ID`, `MAC-адрес`, `порт`, `тип записи (dynamic/static)`. Это значит, что MAC-адрес, изученный в одном VLAN, не виден в других. Адреса изолированы точно так же, как если бы они находились в разных физических коммутаторах.

Широковещательный трафик (ARP-запросы, DHCP Discover и т.п.) ограничивается пределами VLAN. Это уменьшает ненужный “шум” в сети и повышает производительность — один из аргументов, упомянутых в [статье Smart.md](https://www.smart.md/ru/network-equipment-the-importance-of-network-segmentation-and-vlans): «уменьшается перегрузка сети, что приводит к более высокой скорости передачи данных».

### 2.4 Private VLAN (PVLAN)

Для более тонкой изоляции внутри одного IP-подсети существует технология Private VLAN, которая разбивает стандартный VLAN на подкатегории портов:

- **Изолированные (isolated)** порты — могут взаимодействовать только с промисцуозными (обычно шлюзом по умолчанию).
- **Промисцуозные (promiscuous)** порты — обычно соединены с маршрутизатором или сервером; общаются со всеми.
- **Групповые (community)** порты — могут взаимодействовать внутри своей community и с promiscuous.

PVLAN часто используется в хостинге или для изоляции конечных устройств в офисе (например, все ПК не должны видеть друг друга, но должны выходить в интернет через маршрутизатор). В контексте безопасности это предотвращает возможность распространения вредоносного ПО от одного ПК к другому в одном сегменте.

### 2.5 Меж-VLAN маршрутизация и контроль трафика

Взаимодействие между разными VLAN требует маршрутизации на третьем уровне. Два классических способа:

- **Router-on-a-stick** — физический маршрутизатор подключается к коммутатору одним транковым портом, на котором создаются подинтерфейсы, каждый с IP-адресом в своём VLAN. Трафик между VLAN проходит через маршрутизатор, где к нему могут применяться ACL.
- **Switch Virtual Interface (SVI) на L3-коммутаторе** — каждому VLAN назначается виртуальный интерфейс `interface vlan <id>` с IP-адресом, и коммутатор выполняет маршрутизацию аппаратно. Это более производительное решение.

При любом способе меж-VLAN трафик пересекает границу маршрутизации, что даёт точку для применения политик безопасности. Именно здесь SOC-аналитик может разместить правила мониторинга и детектирования.

### 2.6 Угрозы, связанные с VLAN

**VLAN hopping** — атака, позволяющая отправить пакет в чужой VLAN в обход маршрутизации. Две основные техники:

1. **Switch Spoofing** — атакующий эмулирует DTP-сообщения (Dynamic Trunking Protocol) и превращает свой порт в транк, получая доступ ко всем VLAN.
2. **Double Tagging** — злоумышленник отправляет кадр с двумя тегами 802.1Q. Первый тег — native VLAN жертвы, второй — целевой VLAN. Коммутатор, получив кадр на access-порту, где PVID равен первому тегу, снимет внешний тег (считая его native) и отправит кадр дальше с оставшимся тегом в другой VLAN.

Меры противодействия:
- Отключать DTP на портах, подключённых к конечным устройствам (`switchport mode access`, `switchport nonegotiate`).
- Назначать Native VLAN отличным от 1 и не используемым для передачи данных (рекомендуется выделенный unused VLAN).
- Явно прописывать разрешённые VLAN на транках (`switchport trunk allowed vlan`).
- Отключать неиспользуемые порты.

### 2.7 Структурная визуализация потоков

ASCII-схема, иллюстрирующая прохождение тегированного трафика между двумя коммутаторами и маршрутизатором:

```text
[ПК1 (VLAN 10)] ──(untagged)──▶ [Access Port PVID=10] ──(внутренний тег 10)──▶
[Коммутатор A] ──(Trunk, tagged 10,20)──▶ [Коммутатор B] ──(Access Port PVID=20)──▶ [ПК2 (VLAN 20)]

Для общения ПК1 и ПК2 трафик должен пройти через маршрутизатор:
[SVi VLAN 10] --(маршрутизация)--> [SVi VLAN 20] --> выход в нужный VLAN.
```

Таким образом, VLAN создаёт строгие L2-границы, а маршрутизатор (или L3-коммутатор) становится единственной точкой медиации, где можно применить политики безопасности и вести логгирование.

## 3. Практика построения и защиты сегментированной сети

### 3.1 Базовое конфигурирование VLAN (Cisco IOS)

Типовая настройка на коммутаторе Cisco включает создание VLAN, назначение режимов портов и указание native VLAN на транках.

```bash
! Создание VLAN в глобальной конфигурации
vlan 10
 name HR
vlan 20
 name Finance
exit

! Настройка access-портов
interface range GigabitEthernet0/1-8
 switchport mode access
 switchport access vlan 10
 no shutdown

interface GigabitEthernet0/24
 description trunk_to_router
 switchport mode trunk
 switchport trunk native vlan 999   ! Назначаем неиспользуемый VLAN как native
 switchport trunk allowed vlan 10,20
 switchport nonegotiate             ! Отключаем DTP
 no shutdown
```

Для маршрутизации на L3-коммутаторе необходимо включить IP routing и создать SVI:

```bash
ip routing
!
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown
!
interface vlan 20
 ip address 192.168.20.1 255.255.255.0
 no shutdown
```

Теперь устройства в VLAN 10 и 20 могут общаться через шлюзы по умолчанию, если не настроены ACL.

### 3.2 ACL для меж-VLAN безопасности

Сетментная изоляция требует управления трафиком между VLAN. На SVI или подинтерфейсе маршрутизатора применяются Access Control Lists (ACL). Пример: разрешить доступ из VLAN IT (10) к серверу VLAN Finance (20) для протоколов HTTPS и SSH, но запретить всё остальное.

```bash
! Создаём ACL и применяем на SVI VLAN 20 в направлении входящего трафика
ip access-list extended FINANCE-ACL
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.20.10 eq 443
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.20.10 eq 22
 deny   ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255 log   ! Логгируем запреты
 permit ip any any                                 ; остальной трафик разрешён (если нужно)
exit
interface vlan 20
 ip access-group FINANCE-ACL in
```

Ключевой элемент — ключевое слово `log` в правиле deny, которое генерирует syslog-сообщение при каждом срабатывании. Формат сообщения (цифры и IP — иллюстрация):

```
%SEC-6-IPACCESSLOGP: list FINANCE-ACL denied tcp 192.168.10.25(53921) -> 192.168.20.10(80), 1 packet
```

Для SOC это ценный артефакт: он сигнализирует о попытке неавторизованного доступа. На основе таких событий можно создавать правила корреляции, например, при множественных срабатываниях за короткий промежуток времени.

### 3.3 Лучшие практики сегментации

Согласно руководствам [UpGuard](https://www.upguard.com/blog/network-segmentation-best-practices) и [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Network_Segmentation_Cheat_Sheet.html), при проектировании сегментированной сети следует придерживаться ряда принципов:

- **Выделение функциональных зон:** разделяйте сеть на VLAN по ролям: пользовательские рабочие станции, серверы, инфраструктурное управление, гостевой доступ, DMZ. Это облегчит написание правил и мониторинг.
- **Изоляция управления:** management-трафик (SSH, SNMP, веб-интерфейсы к коммутаторам, гипервизорам) должен находиться в отдельном VLAN, доступ к которому открыт только с хостов администраторов. В статье на Habr рекомендуется даже оставить этот VLAN как Native VLAN на случай аварийной замены оборудования.
- **Микросегментация для критичных систем:** серверы СУБД можно изолировать в отдельной подсети с Private VLAN или микро-фаерволом на хосте, разрешая соединения только от серверов приложений.
- **Принцип наименьших привилегий:** меж-VLAN фильтрация должна разрешать только минимально необходимые потоки. Всякое широкое правило “permit ip any any” нарушает смысл сегментации.
- **Мониторинг всех транковых соединений:** непредусмотренные VLAN на транках, внезапные изменения native VLAN — признаки атаки или ошибки конфигурации.
- **Отказ от VLAN 1 для пользовательского трафика:** VLAN 1 часто используется по умолчанию для management-протоколов (CDP, VTP, STP). Его использование для данных создаёт риск непреднамеренного доступа к служебной информации.

Также в [реддит-обсуждении](https://www.reddit.com/r/networking/comments/uicva5/network_segmentation_and_intervlan_security/) отмечается, что наиболее надёжным методом обеспечения безопасности между VLAN является вынос межсетевого экрана нового поколения (NGFW) в точку меж-VLAN маршрутизации, поскольку он обеспечивает инспекцию приложений и защиту от угроз, выходящую за рамки простых ACL.

### 3.4 Инструменты для анализа трафика и инцидентов

Аналитик SOC L1 может использовать:

- **Wireshark / tshark** для захвата и анализа тегированных кадров. В настройках захвата нужно включить фильтр `vlan` или использовать опцию «Capture options → Enable 802.1Q tagging» (в Linux). Просмотр поля VID в деталях кадра позволяет быстро понять, в какой VLAN принадлежит трафик.
- **tcpdump** с поддержкой VLAN-фильтрации. Команда для захвата трафика на VLAN 10 на интерфейсе, принимающем тегированные кадры (Linux с VLAN-интерфейсами): `tcpdump -i eth0.10 -n`. Показать кадр с двумя тегами (double tagging) — важный индикатор атаки.
- **Syslog-серверы и SIEM**: события от коммутаторов и маршрутизаторов о нарушении ACL, изменениях конфигурации (например, изменение режима порта) должны централизованно собираться и коррелироваться. Правила корреляции: «Срабатывание deny в ACL на меж-VLAN маршрутизации» → подозрение на попытку несанкционированного доступа или деятельность вредоносного ПО.

Пример простейшего фильтра Wireshark для отображения кадров конкретного VLAN: `vlan.id == 20`.

### 3.5 Типичные ошибки и как их избежать

1. **Native VLAN совпадает с пользовательским VLAN:** приводит к успешной эксплуатации double tagging. Решение: native VLAN = 999 или другой неиспользуемый, отключённый VLAN.
2. **Порт, подключённый к конечному устройству, оставлен в динамическом режиме (dynamic desirable/auto на Cisco)**, что позволяет атакующему сформировать транк. Решение: жёстко задавать `switchport mode access` и `switchport nonegotiate`.
3. **Отсутствие контроля меж-VLAN трафика:** маршрутизация включена, но ACL не настроены. В этом случае сегментация сведена лишь к ограничению broadcast, а все IP-пакеты проходят свободно. SOC может не заметить lateral movement, так как трафик легитимен с точки зрения маршрутизации.
4. **Раздутая конфигурация транков:** разрешены все VLAN на всех транках — увеличивает поверхность атаки при захвате коммутатора. Рекомендуется использовать `switchport trunk allowed vlan <список>`.
5. **VLAN без SVI:** приводит к невозможности выхода за пределы VLAN, что может как мешать легитимным сервисам, так и ограничивать атакующего. Требуется баланс.

## 4. Сквозной практический пример: внедрение VLAN и контроль межсегментного доступа

### 4.1 Исходные условия

Компания «Контосо» разворачивает сеть в новом офисе. Принято решение о сегментации на основе VLAN для трёх отделов: HR (отдел кадров), Finance (финансовый), IT (информационные технологии). Используется один стек коммутаторов Cisco с поддержкой L3-маршрутизации (Catalyst 9300), в каждый отдел отведён диапазон портов. Цель — запретить прямой IP-обмен между VLAN HR и Finance, сохранив доступ IT-администраторов к серверу в Finance VLAN для обслуживания.

### 4.2 Шаг 1. Создание VLAN и назначение портов

Настройка на коммутаторе:

```bash
! Создаём VLAN
vlan 10
 name HR
vlan 20
 name Finance
vlan 30
 name IT
exit

! Порты для HR (1-8) – access VLAN 10
interface range GigabitEthernet1/0/1-8
 switchport mode access
 switchport access vlan 10
 switchport nonegotiate
 no shutdown
!
! Порты для Finance (9-16) – access VLAN 20
interface range GigabitEthernet1/0/9-16
 switchport mode access
 switchport access vlan 20
 switchport nonegotiate
 no shutdown
!
! Порты для IT (17-24) – access VLAN 30
interface range GigabitEthernet1/0/17-24
 switchport mode access
 switchport access vlan 30
 switchport nonegotiate
 no shutdown
```

Ожидаемый вывод команды `show vlan brief`:

```
VLAN Name                             Status    Ports
---- -------------------------------- --------- -------------------------------
1    default                          active    Gi1/0/25
10   HR                               active    Gi1/0/1, Gi1/0/2, Gi1/0/3, Gi1/0/4, Gi1/0/5, Gi1/0/6, Gi1/0/7, Gi1/0/8
20   Finance                          active    Gi1/0/9, Gi1/0/10, Gi1/0/11, Gi1/0/12, Gi1/0/13, Gi1/0/14, Gi1/0/15, Gi1/0/16
30   IT                               active    Gi1/0/17, Gi1/0/18, Gi1/0/19, Gi1/0/20, Gi1/0/21, Gi1/0/22, Gi1/0/23, Gi1/0/24
1002 fddi-default                     act/unsup
...
```

(Реальные ID портов могут отличаться в зависимости от модели, данная таблица отражает принцип).

### 4.3 Шаг 2. Настройка SVI и маршрутизации

```bash
ip routing

interface vlan 10
 ip address 10.0.10.1 255.255.255.0
 no shutdown

interface vlan 20
 ip address 10.0.20.1 255.255.255.0
 no shutdown

interface vlan 30
 ip address 10.0.30.1 255.255.255.0
 no shutdown
```

После этого устройства в каждом VLAN могут пинговать свой шлюз, а также шлюзы других VLAN, если нет ACL. Маршрутизация между сетями работает по умолчанию.

### 4.4 Шаг 3. Применение ACL для ограничения доступа

Задача: разрешить IT-подсети (10.0.30.0/24) полный доступ к серверу в Finance (10.0.20.10), а для HR (10.0.10.0/24) доступ полностью запретить, логируя попытки. Остальной трафик между VLAN разрешён по минимуму (например, ICMP для диагностики можно разрешить, но мы покажем запрет).

```bash
ip access-list extended FINANCE-FILTER
 permit ip 10.0.30.0 0.0.0.255 host 10.0.20.10
 deny   ip 10.0.10.0 0.0.0.255 host 10.0.20.10 log
 permit ip any any   ! для простоты другой трафик разрешён, кроме явно запрещённого
exit

interface vlan 20
 ip access-group FINANCE-FILTER in
```

При попытке хоста из HR (10.0.10.25) открыть HTTP-соединение на financial server (10.0.20.10:80) пакет будет отброшен, и в лог попадёт сообщение.

### 4.5 Шаг 4. Проверка и анализ логов

С хоста в HR (10.0.10.25) выполняется `curl http://10.0.20.10`. Результат — тайм-аут, соединений нет. В syslog коммутатора появляется запись (пример):

```
Aug 10 08:12:54.123: %SEC-6-IPACCESSLOGP: list FINANCE-FILTER denied tcp 10.0.10.25(49281) -> 10.0.20.10(80), 1 packet
```

Для SOC-аналитика это событие может быть настроено как алерт правилом корреляции: «Denied inter-VLAN traffic from HR to Finance host». При многократных попытках в течение окна времени — эскалация до инцидента.

### 4.6 Шаг 5. Обнаружение попытки несанкционированного доступа

Дополнительный сценарий: злоумышленник, получивший доступ к компьютеру в HR, пытается сканировать сервер в Finance. ACL блокирует трафик, но генерирует множественные сообщения. В SIEM-системе правило детектирования на базе частоты срабатывания за минуту:

```text
| stats count by src_ip, dest_ip where vendor="Cisco" AND event_id="SEC-6-IPACCESSLOGP" AND protocol="tcp"
```

Выявление всплеска с одного src_ip — повод для немедленной проверки. Таким образом сегментация не только предотвратила доступ, но и предоставила видимый в SIEM след.

### 4.7 Ожидаемый вывод примера

Пример демонстрирует, как конфигурация VLAN в сочетании с меж-VLAN ACL позволяет реализовать многоуровневую защиту. VLAN изолируют широковещательные домены, ACL ограничивают сетевой доступ между сегментами, а логирование даёт SOC инструмент для обнаружения подозрительной активности. Такой подход соответствует принципу defence in depth и напрямую противодействует lateral movement.
