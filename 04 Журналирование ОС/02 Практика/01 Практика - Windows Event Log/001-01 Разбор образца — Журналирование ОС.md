**Сценарий.** Банк «ФинТраст», 23 марта 2026, 03:00. SIEM поднял правило «множественные неудачные входы». Аналитик L1 выгрузил события входа из Security-лога файлового сервера `SRV-FILE-01` (`wevtutil qe Security /f:xml`).

**Исходные данные.** Файл `security-discovery.xml`. Одно из неудачных и итоговое успешное события (поля сокращены):

```xml
<Event ...>
  <System><EventID>4625</EventID> ... <Channel>Security</Channel>
    <Computer>SRV-FILE-01.corp.local</Computer></System>
  <EventData>
    <Data Name="TargetUserName">Administrator</Data>
    <Data Name="SubStatus">0xc000006a</Data>
    <Data Name="LogonType">3</Data>
    <Data Name="IpAddress">45.135.232.18</Data>
  </EventData>
</Event>
<Event ...>
  <System><EventID>4624</EventID> ... </System>
  <EventData>
    <Data Name="TargetUserName">Administrator</Data>
    <Data Name="LogonType">3</Data>
    <Data Name="IpAddress">45.135.232.18</Data>
  </EventData>
</Event>
```

**Задача.** Восстановить картину перебора пароля и снять её атрибуты.

**Решение по шагам.**

**Шаг 1 — найти неудачные входы.** События `4625` — неудачный вход. У всех в этой выгрузке `SubStatus = 0xc000006a` (неверный пароль), одна и та же `TargetUserName` и один `IpAddress`.

**Контрольный вопрос 1.1.** На какую учётную запись шёл перебор? **Ответ:** `Administrator`

**Контрольный вопрос 1.2.** С какого IP-адреса шёл перебор? **Ответ:** `45.135.232.18`

**Шаг 2 — посчитать попытки.** Считаем число событий `4625` для этой учётки.

**Контрольный вопрос 1.3.** Сколько событий `4625` в выгрузке? **Ответ:** `6`

**Шаг 3 — найти успех.** После серии `4625` идёт событие `4624` (успешный вход) для той же учётки с того же IP — перебор удался.

**Контрольный вопрос 1.4.** Какой EventID у события успешного входа? **Ответ:** `4624`

**Контрольный вопрос 1.5.** Какой тип входа использовался? **Ответ:** `3`

**Вердикт.** True Positive: успешный перебор пароля учётки `Administrator` с `45.135.232.18` (6 неудач, затем успех, тип входа 3 — сетевой). Снять атрибуты, эскалировать.

**Готовый результат.** В тикет: brute-force на `Administrator` с `45.135.232.18`, 6× `4625` → `4624`, `LogonType 3`, вердикт TP.

**Ключевые уроки.**
- Аудит входа: `4624` — успех, `4625` — неудача; поля — в `<EventData>` по `Name`.
- `LogonType`: `2` интерактивный (консоль), `3` сетевой (SMB/NTLM), `10` RDP.
- Серия `4625` для одной учётки с одного IP + последующий `4624` = успешный перебор пароля.
- `SubStatus 0xc000006a` означает «неверный пароль»; состав аудита задаётся групповой политикой.
