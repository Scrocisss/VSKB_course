**Сценарий.** Хостинг-провайдер «ОблакоСервис», 23 марта 2026, 03:15. Сработало правило о множественных неудачных входах по SSH на `srv-web-1`. Аналитик L1 выгрузил `/var/log/auth.log`.

**Исходные данные.** Файл `auth-discovery.log` (фрагмент):

```
Apr 20 03:11:09 srv-web-1 sshd[2840]: Failed password for root from 45.135.232.18 port 51000 ssh2
... (ещё неудачные) ...
Apr 20 03:12:40 srv-web-1 sshd[2840]: Accepted password for root from 45.135.232.18 port 51890 ssh2
Apr 20 03:12:40 srv-web-1 sshd[2840]: pam_unix(sshd:session): session opened for user root by (uid=0)
```

**Задача.** Восстановить картину входа и снять её атрибуты.

**Решение по шагам.**

**Шаг 1 — отделить внешние входы.** Кроме штатного входа `deploy` с внутреннего `192.168.5.12`, есть события для `root` с публичного `45.135.232.18`. Вход `root` извне — аномалия (прямой вход root по SSH обычно запрещён).

**Контрольный вопрос 1.1.** На какую учётную запись выполнен успешный вход с внешнего адреса? **Ответ:** `root`

**Контрольный вопрос 1.2.** С какого IP-адреса выполнен вход? **Ответ:** `45.135.232.18`

**Шаг 2 — посчитать неудачные попытки.** Перед `Accepted` идёт серия `Failed password` для `root` с того же IP — перебор пароля.

**Контрольный вопрос 1.3.** Сколько событий `Failed password` в логе? **Ответ:** `7`

**Шаг 3 — определить метод входа.**

**Контрольный вопрос 1.4.** Каким методом аутентификации выполнен успешный вход? **Ответ:** `password`

**Контрольный вопрос 1.5.** Какая служба обработала вход? **Ответ:** `sshd`

**Вердикт.** True Positive: успешный перебор пароля `root` по SSH с `45.135.232.18` (7 неудач, затем успех). Снять атрибуты, эскалировать.

**Готовый результат.** В тикет: SSH-брутфорс `root` с `45.135.232.18`, 7× `Failed` → `Accepted password`, вердикт TP.

**Ключевые уроки.**
- `/var/log/auth.log` — аутентификация: `sshd` (вход по SSH), `sudo`, `su`; `syslog` — общие сообщения, `kern.log` — ядро, `audit.log` — auditd.
- `sshd`: `Failed|Accepted password|publickey for USER from IP port N ssh2`.
- Серия `Failed` + `Accepted` для одной учётки с одного IP = успешный SSH-брутфорс.
- Вход `root` напрямую или служебной учётки с внешнего адреса — аномалия; `Accepted publickey` без неудач может означать кражу ключа.
