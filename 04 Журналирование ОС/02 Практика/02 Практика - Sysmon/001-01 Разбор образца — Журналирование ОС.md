**Покрывает листья** (ветка «Журналирование ОС / Windows / Sysmon»):
- Ценность Sysmon для аналитика L1
- Конфигурация Sysmon для аналитика L1
- Ключевые события Sysmon

**Сценарий.** Банк «ФинТраст», 23 марта 2026, 08:15. EDR/Sysmon отметил запуск PowerShell из Word на станции бухгалтерии `WS-ACC-04`. Аналитик L1 выгрузил события Sysmon Event ID 1.

**Исходные данные.** Файл `sysmon1-discovery.xml`. Подозрительное событие (поля сокращены):

```xml
<Event ...>
  <System><EventID>1</EventID>
    <Channel>Microsoft-Windows-Sysmon/Operational</Channel></System>
  <EventData>
    <Data Name="ProcessId">6620</Data>
    <Data Name="Image">C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe</Data>
    <Data Name="CommandLine">powershell.exe -NoProfile -WindowStyle Hidden -EncodedCommand JABjAD0A...</Data>
    <Data Name="User">CORP\jsmith</Data>
    <Data Name="Hashes">SHA256=C515E8E7D219F83538D2B67A22458DCF00E518F53376AC1706C83DF3948BE2ED</Data>
    <Data Name="ParentImage">C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE</Data>
    <Data Name="ParentCommandLine">"...WINWORD.EXE" /n "C:\Users\jsmith\Downloads\Invoice_4471.docm"</Data>
  </EventData>
</Event>
```

**Задача.** Найти подозрительную связку «родитель → потомок» и снять её атрибуты.

**Решение по шагам.**

**Шаг 1 — прочитать связку процессов.** `ParentImage` — это `WINWORD.EXE` (Word), а `Image` — `powershell.exe`. Word, запускающий PowerShell, — типичный признак вредоносного макроса из документа (здесь `Invoice_4471.docm`).

**Контрольный вопрос 1.1.** Полный путь дочернего процесса? **Ответ:** `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`

**Контрольный вопрос 1.2.** Какой родительский процесс его запустил? **Ответ:** `WINWORD.EXE`

**Шаг 2 — снять идентификаторы для тикета.**

**Контрольный вопрос 1.3.** Какой PID у дочернего процесса? **Ответ:** `6620`

**Контрольный вопрос 1.4.** Какой SHA256-хэш у образа дочернего процесса? **Ответ:** `C515E8E7D219F83538D2B67A22458DCF00E518F53376AC1706C83DF3948BE2ED`

**Контрольный вопрос 1.5.** Под каким пользователем запущен процесс? **Ответ:** `CORP\jsmith`

**Вердикт.** True Positive: Word породил скрытый PowerShell с `-EncodedCommand` (вредоносный макрос из `Invoice_4471.docm`). Снять связку, PID, хэш, пользователя; хэш проверить по репутации, эскалировать.

**Готовый результат.** В тикет: `WINWORD.EXE → powershell.exe` (PID 6620), `-EncodedCommand`, пользователь `CORP\jsmith`, SHA256 для проверки, вердикт TP — макрос-загрузчик.

**Ключевые уроки.**
- Sysmon (канал `Microsoft-Windows-Sysmon/Operational`) даёт то, чего нет в штатном логе: `CommandLine`, `ParentImage`, `Hashes`.
- Event ID 1 — создание процесса; связка `ParentImage → Image` — ключ к выявлению аномалий.
- Офисное приложение → интерпретатор (`powershell`/`cmd`/`mshta`/`wscript`) = признак вредоносного макроса.
- Хэш (`Hashes`) проверяется по репутации (VirusTotal — см. раздел обогащения).
