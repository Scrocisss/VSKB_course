**Сценарий.** Хостинг-провайдер «ОблакоСервис», 23 марта 2026, 12:30. Правило auditd `identity` сработало на сервере `web-prod-3`. Аналитик L1 выгрузил соответствующие записи из `audit.log`.

**Исходные данные.** Файл `audit-discovery.log`. Подозрительная пара записей:

```
type=SYSCALL msg=audit(1776661290.216:5209): arch=c000003e syscall=59 success=yes exit=0 ... ppid=2810 pid=3120 auid=1001 uid=0 gid=0 euid=0 ... tty=pts1 ses=7 comm="useradd" exe="/usr/sbin/useradd" key="identity"
type=EXECVE msg=audit(1776661290.216:5209): argc=8 a0="useradd" a1="-o" a2="-u" a3="0" a4="-M" a5="-s" a6="/bin/bash" a7="sysd"
```

**Задача.** Разобрать подозрительный запуск и снять его атрибуты.

**Решение по шагам.**

**Шаг 1 — прочитать SYSCALL-запись.** `comm` и `exe` показывают, что выполнено: `useradd` (`/usr/sbin/useradd`). `key="identity"` — сработало правило аудита изменений учётных записей.

**Контрольный вопрос 1.1.** Какая программа выполнена? **Ответ:** `useradd`

**Контрольный вопрос 1.2.** Каков полный путь исполняемого файла? **Ответ:** `/usr/sbin/useradd`

**Шаг 2 — прочитать, кто и под кем.** `auid=1001` (вошёл обычный пользователь с loginuid 1001), `uid=0` — команда выполнена с правами root: пользователь поднялся до root.

**Контрольный вопрос 1.3.** Какой `auid`? **Ответ:** `1001`

**Контрольный вопрос 1.4.** Под каким `uid` выполнена команда? **Ответ:** `0`

**Шаг 3 — прочитать аргументы (EXECVE).** Команда `useradd -o -u 0 -M -s /bin/bash sysd` создаёт учётную запись `sysd` с `-u 0` (UID 0 — права root) и `-o` (разрешить дубль UID). Это создание root-бэкдора.

**Контрольный вопрос 1.5.** Имя создаваемой учётной записи? **Ответ:** `sysd`

**Вердикт.** True Positive: пользователь (`auid=1001`, поднявшийся до `uid=0`) создал root-бэкдор `useradd -o -u 0 … sysd`. Снять команду, auid/uid, имя учётки; эскалировать.

**Готовый результат.** В тикет: `useradd -o -u 0 -M -s /bin/bash sysd`, `auid=1001`, `uid=0`, создан root-бэкдор `sysd`, вердикт TP.

**Ключевые уроки.**
- `auditd` перехватывает syscall по правилам, пишет в `/var/log/audit/audit.log`; `execve` (`syscall=59`) — запуск программы.
- Событие = пара записей с общим `msg`: `SYSCALL` (контекст) + `EXECVE` (аргументы `a0…aN`).
- `auid` (loginuid) сохраняется через `su`/`sudo`: `auid` обычного пользователя при `uid=0` = поднялся до root.
- Подозрительные `execve`: `useradd -u 0`, `chmod 4755` (SUID), загрузка из `/tmp`/`/dev/shm`; поле `key` подсказывает категорию правила.
