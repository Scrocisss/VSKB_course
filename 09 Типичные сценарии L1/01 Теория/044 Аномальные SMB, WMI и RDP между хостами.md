# Аномальные SMB, WMI и RDP в контексте латерального движения: обнаружение на уровне SOC L1

## 1. Латеральное движение и протоколы удалённого взаимодействия: базовые понятия и разграничения

Латеральное движение (lateral movement) — это совокупность техник, применяемых злоумышленником после первоначального проникновения для перемещения по внутренней сети организации от одной скомпрометированной системы к другой. Цель — расширение зоны контроля, повышение привилегий и достижение критичных ресурсов: контроллеров домена, файловых серверов, серверов баз данных. В модели MITRE ATT&CK тактика Lateral Movement (TA0008) включает десятки техник, значительная часть которых эксплуатирует легитимные протоколы и службы Windows, такие как SMB, WMI и RDP.

Эти три механизма объединяет способность обеспечивать удалённое исполнение кода, передачу файлов или интерактивный доступ, при этом они повсеместно используются для администрирования. Злоумышленники злоупотребляют ими именно потому, что грань между штатной работой администратора и вредоносной активностью крайне тонка. SOC L1 обязан понимать не только техническую суть каждого протокола, но и типичные индикаторы их аномального использования, чтобы своевременно переводить подозрительные события в инциденты и эскалировать их аналитикам L2.

**SMB (Server Message Block)** — сетевой протокол прикладного уровня, обеспечивающий общий доступ к файлам, принтерам и межпроцессное взаимодействие через именованные каналы (named pipes) в Windows. По умолчанию работает на порту 445 (в современных системах) или 139 (NetBIOS). В контексте латерального движения SMB выступает как транспорт для копирования вредоносных файлов на удалённые машины через административные общие папки (ADMIN$, C$, IPC$), а также для удалённого создания и запуска служб через интерфейс Service Control Manager (SCM) поверх DCE/RPC. Атаки на базе SMB включают передачу хэшей (Pass-the-Hash) с использованием NTLM-аутентификации через SMB, выполнение команд с помощью PsExec и аналогичных утилит, а также прямое перемещение по сети с использованием встроенной команды `net use`.

**WMI (Windows Management Instrumentation)** — инфраструктура управления и контроля, встроенная в Windows, реализующая доступ к параметрам и объектам операционной системы через модель CIM (Common Information Model). WMI позволяет удалённо запрашивать информацию, настраивать систему и создавать процессы. Для латерального движения злоумышленники используют WMI для выполнения команд на целевых машинах через класс `Win32_Process` методом `Create`, а также для создания постоянных подписок на события (WMI Event Subscription), обеспечивающих персистентность. Трафик WMI инкапсулируется в DCOM/RPC, порты динамически выделяются в диапазоне 49152–65535 (с ключевым начальным подключением к порту 135 — служба RPC Endpoint Mapper), что затрудняет фильтрацию.

**RDP (Remote Desktop Protocol)** — проприетарный протокол Microsoft, предоставляющий интерактивный графический доступ к удалённому рабочему столу. Стандартный порт TCP 3389. В атаках RDP используется для получения интерактивного контроля над скомпрометированной системой, дальнейшего перемещения на другие хосты (RDP-прыжки), а также как канал для обратного подключения после взлома. Хотя RDP сам по себе не предоставляет средств удалённого выполнения команд без участия пользователя, злоумышленники комбинируют его с инструментами администрирования, уже имеющимися на конечной точке. Аномальная RDP-активность часто проявляется в виде входящих подключений с нестандартных учётных записей, нетипичных временных меток или соединений с серверами, на которых RDP ранее не использовался.

У всех трёх протоколов есть легитимные административные варианты использования; ключ к обнаружению — выявление отклонений от базовой линии поведения в отношении субъекта, времени, частоты и источника подключений. Разграничение этих механизмов по назначению, сетевым характеристикам и возможностям детектирования приведено в таблице ниже.

| Характеристика | SMB (Server Message Block) | WMI (Windows Management Instrumentation) | RDP (Remote Desktop Protocol) |
|----------------|-----------------------------|-------------------------------------------|--------------------------------|
| **Основное назначение** | Общий доступ к файлам, принтерам, IPC | Удалённое управление и мониторинг системы | Интерактивный удалённый рабочий стол |
| **Типичные порты / протоколы** | TCP 445 (SMB поверх TCP), TCP 139 (NetBIOS), UDP 137-138 (NetBIOS) | TCP 135 (RPC Endpoint Mapper) + динамические TCP (49152–65535) | TCP 3389 |
| **Применение в латеральном движении** | Копирование файлов через Admin Shares (C$, ADMIN$), выполнение через PsExec, Pass-the-Hash | Удалённый запуск процессов (`Win32_Process.Create`), подписка на события (persistence) | Интерактивное перемещение между хостами, RDP-прыжки, backdoor-доступ |
| **Характерный лог-источник** | События службы SMB/Security (4776, 4624/4625 тип 3), журналы UAL | Microsoft-Windows-WMI-Activity/Operational, событие 5861 (WMI Activity), Sysmon (Event ID 1, 19, 20) | События Logon (4624/4625 тип 10), Microsoft-Windows-TerminalServices-LocalSessionManager/Operational |
| **Индикаторы аномального поведения** | Подключения к ADMIN$ от непривилегированных хостов, высокая частота сессий 4624 тип 3 в короткий промежуток, использование NTLMv1 | Запуск подозрительных процессов (cmd, powershell) через WMI, временные подписки без документирования | Входы в нерабочее время, RDP с недоверенных IP, вход с учётных записей, неиспользуемых для RDP |
| **Методы подавления шума для детекта** | Мониторинг сессионных токенов, фильтрация NetBIOS на межхостовом уровне | Ограничение WMI административными подсетями, аудит удалённого вызова методов | Ограничение RDP группами пользователей, Network Level Authentication (NLA) |

Раздел закладывает основу для понимания предмета: латеральное движение — не единичное действие, а последовательность шагов, где SMB, WMI и RDP выступают как инструменты. Для специалиста SOC L1 критически важно распознавать не столько отдельные события, сколько цепочки: например, аутентификация SMB (событие 4624 тип 3) с последующим созданием процесса (событие Sysmon Event ID 1) на целевом хосте.

## 2. Механизмы злоупотребления SMB, WMI и RDP в цепочке атаки

Внутреннее устройство латерального движения через эти протоколы укладывается в несколько стандартных паттернов, описанных в фреймворке MITRE ATT&CK [url с источника отсутствует, но техники общеизвестны]. Ключевой фактор успеха атакующего — наличие скомпрометированных учётных данных или хэшей, позволяющих проходить аутентификацию, и возможность сетевого взаимодействия с целевым хостом по соответствующему протоколу. Рассмотрим каждый протокол с точки зрения исполняемых этапов и порождаемых артефактов.

### 2.1 SMB как транспорт и исполнитель

Техника **Remote Services: SMB/Windows Admin Shares** (T1021.002) базируется на возможности подключения к скрытым административным общим папкам через SMB с правами администратора. Атакующий после компрометации одной машины и кражи учётных данных (например, через дамп LSASS) проверяет доступность ADMIN$ на целевых хостах, затем копирует туда полезную нагрузку и запускает её удалённо.

Цепочка типовой атаки через PsExec (T1569.002) выглядит так:
1. Подключение к административной шаре: `net use \\target\ADMIN$ /user:Domain\AdminUser` — успешная аутентификация создаёт событие учётной записи и сетевой сеанс.
2. Копирование исполняемого файла на целевой хост (через SMB).
3. Удалённое создание и запуск службы через SCM (Service Control Manager) с использованием DCE/RPC поверх SMB. При этом создаётся именованный канал `\PIPE\ntsvcs`. На целевом хосте создаётся служба, исполняющая скопированный файл, и генерируется событие создания процесса.
4. После выполнения злоумышленник удаляет службу и файлы, чтобы замести следы.

В варианте Pass-the-Hash (T1550.002) атакующий использует NTLM-хэш напрямую для аутентификации по SMB без знания пароля. Инструменты, такие как Mimikatz, Impacket (wmiexec.py, smbexec.py), встроенные утилиты с флагом `/hash` в PsExec, позволяют выполнить команду на удалённой системе с помощью одной команды.

Аномальное поведение SMB, на которое должен реагировать SOC L1:
- Множественная сетевая аутентификация типа 3 (идентификатор события 4624 в журнале Security) с одной исходной машины на разные хосты в течение короткого времени.
- Подключение к ADMIN$ или IPC$ с рабочих станций, где это никогда не наблюдалось.
- Использование NTLM-аутентификации (не Kerberos) в среде, где преобладает Kerberos, или использование NTLMv1.
- Срабатывание правил защиты от атак (например, ASR-правило Windows Defender "Block process creations originating from PSExec and WMI commands") с последующим аудиторингом события.

### 2.2 WMI: удалённое выполнение и персистентность

Техника **Windows Management Instrumentation** (T1047) реализуется через DCOM-подключение к пространству имён `root\cimv2` на удалённой системе. Атакующий, обладая правами администратора, выполняет метод `Create` класса `Win32_Process` для запуска произвольного кода, например, PowerShell-скрипта или загрузчика. Команда может выглядеть так (с помощью встроенной утилиты `wmic`):
```bash
wmic /node:"target.example.com" /user:"DOMAIN\user" /password:"Pass" process call create "cmd.exe /c powershell -enc <Base64>"
```
Современные инструменты, такие как Cobalt Strike, используют WMI для запуска beacon’ов. Характерная особенность — процесс-родитель для создаваемого процесса: при удалённом запуске через WMI родителем будет `WmiPrvSE.exe`, а не обычная оболочка.

Для персистентности злоумышленники регистрируют WMI Event Subscriptions (T1546.003), которые срабатывают при определённых условиях (старт системы, вход пользователя) и выполняют вредоносный код. В этом случае создаются экземпляры классов `__EventFilter`, `__EventConsumer` и `__FilterToConsumerBinding` в пространстве имён root\subscription. В логах остаются артефакты: события WMI Activity.

Аномалии WMI, релевантные для L1:
- Резкий рост активности WMI, фиксируемый через событие 5861 ("WMI Temporary Event Created"), особенно если подписка не документирована в CMDB.
- Удалённые вызовы методов WMI с хостов, не являющихся серверами управления.
- Процессы, запущенные родителем `WmiPrvSE.exe` с необычными аргументами (cmd.exe, powershell.exe, mshta.exe).
- Сетевые подключения к порту 135 с последующим динамическим RPC-трафиком между хостами, не типичными для данной роли.

### 2.3 RDP: интерактивное продвижение и удержание

RDP (T1021.001) обеспечивает полноценный графический сеанс. Злоумышленник, получив учётные данные, инициирует RDP-сессию к целевому серверу или рабочей станции. Особенность — событие входа с типом 10 (RemoteInteractive) и идентификатором GUID, фиксируемое в журнале Security (4624). Дополнительная информация: IP-адрес клиента, номер сеанса.

Аномальные паттерны RDP, требующие эскалации:
- Тип входа 10 для учётной записи, которая никогда не использовала RDP (особенно привилегированной).
- Вход в нерабочее время или из нетипичной географической локации (индикатор выявляется через анализ сетевых данных или обогащение GeoIP).
- Последовательные множественные RDP-сессии от одного пользователя, проходящие через несколько хостов за короткое время (RDP-прыжки).
- Модификация реестра, разрешающая RDP (`fDenyTSConnections = 0`), зафиксированная непосредственно перед первым входом, если ранее RDP был отключён.
- Аномально большое количество успешных или неудачных попыток входа (событие 4625 тип 10), что может указывать на брутфорс.

Для оценки нормального уровня используется система правил обнаружения, основанная на машинном обучении или статистике, например, в Elastic Security с пакетом Lateral Movement Detection. Такие системы вычисляют аномальную вероятность для событий RDP, учитывая исторические паттерны.

### Структурная схема типового SMB/WMI/RDP латерального движения

```text
[Исходный хост скомпрометирован] ──кража хэшей (Mimikatz)──▶ [Атакующий]
           │
           ├── Порт 445 (SMB) ──▶ Административная шара \\target\ADMIN$
           │                         ├── копирование payload.exe
           │                         └── создание службы (DCE/RPC) ── процесс payload.exe
           │
           ├── Порт 135 (RPC) + динамические ——▶ WMI Win32_Process.Create("cmd /c ...")
           │                                      └── процесс WmiPrvSE.exe → cmd.exe (на целевом)
           │
           └── Порт 3389 (RDP) ──▶ Интерактивный вход (тип 10), сессия с GUI
                                   └── дальнейший запуск инструментов вручную
```

Атакующий комбинирует эти методы: например, сначала подключается через RDP для разведки, затем копирует через SMB инструментарий и выполняет его через WMI либо напрямую через создание службы. SOC L1 должен уметь восстанавливать такую цепочку, связывая события аутентификации, создания процессов и сетевых подключений.

## 3. Практика обнаружения аномальной активности SMB, WMI и RDP для аналитика L1

Обнаружение латерального движения через SMB, WMI и RDP строится на корреляции данных из нескольких источников: журналов аудита Windows (Security, WMI-Activity, TerminalServices), Sysmon, сетевых потоков (NetFlow, sFlow) и данных EDR. Аналитик L1 работает с готовыми правилами детектирования, алертами SIEM и гранулированными запросами на поиск угроз. Рассмотрим ключевые практические аспекты.

### 3.1 Источники данных и типовые запросы

**Журнал Security** — основной источник событий аутентификации:
- Событие **4624** (успешный вход): поля Logon Type и Workstation Name. Тип 3 — сетевая аутентификация (характерна для SMB и WMI), тип 10 — RemoteInteractive (RDP). Критично сопоставлять эти события с парой 4672 (привилегированный вход) и с процессом, инициировавшим вход (если есть Sysmon).
- Событие **4625** — неудачный вход. Высокая частота может указывать на брутфорс RDP или SMB-атаку.
- Событие **4776** — проверка учётных данных NTLM (доменный контроллер). Позволяет видеть, когда атакующий пытается использовать хэш для SMB.
- Событие **5140** — обращение к общей папке (включая ADMIN$, IPC$). Полезно фиксировать факт доступа.

**Журналы Sysmon** расширяют данные о процессах и сетевых подключениях:
- Event ID **1** (создание процесса) — содержит поля ParentImage, Image, CommandLine. Для WMI родителем будет WmiPrvSE.exe; для запуска через PsExec — образ службы psexesvc.exe.
- Event ID **3** (сетевое подключение) — фиксирует исходящие соединения. SMB на порт 445, WMI — исходящий RPC, RDP — 3389. Полезно для выявления необычных направлений трафика.
- Event ID **10** (обнаружен доступ к процессу) — может фиксировать чтение памяти LSASS.

**Журнал WMI-Activity/Operational** позволяет отслеживать подписки и вызовы методов, но часто не включён по умолчанию. Событие **5861** (WMI Temporary Event Created) — критический индикатор создания временной WMI-подписки.

**Сетевые данные:** анализ flow-записей между хостами помогает обнаружить внезапный рост трафика на портах 445, 135, 3389, особенно если источник — рабочая станция, а не сервер.

### 3.2 Примеры правил детектирования и поисковой аналитики

Аналитик L1 ежедневно работает с SIEM-правилами, ниже приведены иллюстративные сигнатуры (структура, а не конкретный рабочий запрос), адаптированные под общие подходы Sigma-правил или SPL.

**Аномальный вход по SMB с использованием NTLM**  
Правило отслеживает событие 4624 (logon type 3) с пакетом аутентификации NTLM вместо Kerberos на группе серверов, где должно применяться Kerberos.  
Illustrative structure in Sigma format:
```yaml
title: Potential Pass-the-Hash via SMB
logsource:
  product: windows
  service: security
detection:
  selection:
    EventID: 4624
    LogonType: 3
    AuthenticationPackageName: 'NTLM'
    TargetUserName: 'Administrator'
  filter_legit:
    SourceWorkstation: 'SRV-LEGIT-*'
  condition: selection and not filter_legit
```
Аналитик видит алерт, проверяет исходный хост, время и связывает с другими событиями (например, 4776 на DC, где пользователь и рабочая станция не совпадают с типовым паттерном).

**Обнаружение удалённого создания процесса через WMI**  
Поиск по Sysmon Event ID 1, где родитель — WmiPrvSE.exe, а дочерний процесс — cmd.exe, powershell.exe или иной нестандартный для этой роли.  
Пример поискового запроса в Splunk:
```spl
index=windows source="WinEventLog:Microsoft-Windows-Sysmon/Operational" EventID=1
ParentImage="*\\WmiPrvSE.exe" Image IN ("*\\cmd.exe", "*\\powershell.exe", "*\\wscript.exe")
| table _time, host, User, ParentImage, Image, CommandLine
```
Вывод может показать неожиданный запуск на нескольких хостах с общей исходной машиной.

**Обнаружение аномальных RDP-сессий**  
Простой запрос для выявления входов тип 10 для учётных записей группы "Domain Admins" в нерабочие часы (с 22:00 до 06:00):
```spl
index=wineventlog sourcetype="WinEventLog:Security" EventCode=4624 Logon_Type=10
| eval Hour=strftime(_time, "%H")
| where Hour > 22 OR Hour < 6
| search TargetUserName IN ("Admin1", "Admin2")
| table _time, TargetUserName, Source_Network_Address, host
```
При обнаружении подозрительных записей аналитик обогащает их данными о местоположении IP и проверяет смежные события.

### 3.3 Типичные ошибки и стратегии приоритизации

Наибольшая сложность для L1 — высокий уровень ложноположительных срабатываний, вызванных работой легитимных средств управления (SCCM, System Center, скрипты инвентаризации). Поэтому необходимо постоянно поддерживать списки исключений (whitelist) для административных подсетей, сервисных учётных записей и известных плановых заданий. Критично различать разовый легитимный запуск и систематическое перемещение по сети. Практический подход:
1. При получении алерта на необычный SMB-доступ проверить, не совпадает ли он с плановой задачей: сверить время с расписанием резервного копирования или spreading-патча.
2. Для WMI — проверить, исходит ли вызов от управляющего сервера или от рабочей станции, и если последнее — это всегда эскалация, даже если команда безобидна.
3. Для RDP — всегда сопоставлять с VPN-сессией источника, географией и историей входов учётной записи.

Аналитик L1 не проводит глубокого расследования, но обязан зафиксировать контекст: источник, цель, временные метки, запись последующих событий (например, кто вошёл через RDP и затем запустил процессы). Затем пакет передаётся L2 с пометкой о подозрительной активности.

## 4. Сквозной практический пример: от алерта на аномальный WMI-запуск до фиксации латерального движения с использованием SMB и RDP

**Исходные условия:**  
Среда: домен Windows, развёрнута SIEM Splunk, коллекция логов Windows Security, Sysmon и UAL с серверов. Аналитик L1 получает автоматический алерт от корреляционного правила, обнаружившего подозрительную активность WMI.

### Шаг 1. Получение и оценка алерта WMI
Алерт: "Potential Remote WMI Execution" с исходного хоста `WS-PC01` (рабочая станция) на `DC01` (контроллер домена), процесс: `WmiPrvSE.exe` запустил `cmd.exe` с командной строкой, содержащей кодированный PowerShell.
```spl
index=sysmon EventID=1 host="DC01" ParentImage="*\\WmiPrvSE.exe"
| table _time, ParentImage, Image, CommandLine
```
Пример вывода:
```
_time: 2026-02-15T23:12:45
ParentImage: C:\Windows\System32\wbem\WmiPrvSE.exe
Image: C:\Windows\System32\cmd.exe
CommandLine: "cmd.exe" /c powershell -enc JABjAGwAaQBlAG4AdAAgAD0AIABOAGUAdw...==
```
Аналитик фиксирует, что запуск произошёл в ночное время, с хоста не являющегося сервером управления, и на контроллере домена, что нетипично. Это немедленно классифицируется как инцидент и ожидает эскалации, но предварительно аналитик проверяет смежную активность.

### Шаг 2. Поиск предшествующей SMB-активности
Проверяется, как злоумышленник мог подготовить WMI-запуск. Запрос к событиям Security на DC01 для поиска доступа к ADMIN$ (событие 5140) и успешных аутентификаций сетевого типа (4624 тип 3) с исходной машины `WS-PC01` за 5 минут до инцидента.
```spl
index=wineventlog host="DC01" (EventCode=5140 OR (EventCode=4624 Logon_Type=3)) Source_Network_Address=192.168.1.101
| table _time, EventCode, TargetUserName, IpAddress, ShareName
```
Результат:
```
_time: 2026-02-15T23:11:50, EventCode:5140, ShareName: \\*\ADMIN$, IpAddress: 192.168.1.101, User: DOMAIN\admin_user
_time: 2026-02-15T23:11:51, EventCode:4624, Logon_Type:3, TargetUserName: admin_user, IpAddress: 192.168.1.101
```
Это подтверждает, что за 1 минуту до WMI была успешная аутентификация по SMB и обращение к административной общей папке. Логичный вывод: атакующий скопировал через SMB инструменты или использовал этот доступ для легитимного запуска WMI с украденными учётными данными.

### Шаг 3. Проверка RDP-сессий
Далее аналитик проверяет, не использовал ли злоумышленник RDP для интерактивного перемещения. Запрос к событиям Logon тип 10 на DC01 и других серверах с тем же пользователем в течение часа.
```spl
index=wineventlog EventCode=4624 Logon_Type=10 TargetUserName="admin_user"
| table _time, host, Source_Network_Address
```
Вывод:
```
_time: 2026-02-15T23:05:10, host: WS-PC01, Source_Network_Address: 198.51.100.45 (внешний VPN-адрес)
_time: 2026-02-15T23:15:02, host: DC01, Source_Network_Address: 192.168.1.101
```
Первый вход с внешнего IP показывает, что изначально злоумышленник вошёл на рабочую станцию через RDP с VPN-концентратора (возможно, скомпрометированная учётка). Затем, с того же рабочего места, последовал вход на DC01 через RDP, но с локального IP той же рабочей станции (RDP-прыжок). Аналитик фиксирует эту цепочку как признак латерального движения.

### Шаг 4. Поиск дальнейшего перемещения с помощью UAL и Sysmon
Чтобы оценить масштаб, аналитик использует данные UAL (User Access Logging) с сервера DC01 для выявления доступа к серверным ролям (например, File Server) после подозрительного RDP-входа.
```text
Get-UAL | Where-Object { $_.UserName -eq 'admin_user' -and $_.SourceAddress -eq '192.168.1.101' }
```
Вывод может содержать записи о доступе к файловым ресурсам других серверов, что укажет на дальнейшую SMB-активность. Одновременно запрашивается Sysmon с целевых серверов для выявления процессов типа `psexesvc.exe` или повторных WMI-запусков.

### Шаг 5. Формирование отчёта и эскалация
Собранные доказательства укладываются в последовательность:
- Внешний RDP вход на WS-PC01 (с VPN IP) под учётной записью admin_user.
- С этой машины — аутентификация SMB и доступ к ADMIN$ на DC01, с последующим запуском кодированного PowerShell через WMI.
- Далее — RDP сессия с WS-PC01 на DC01 для интерактивного управления, и возможно, доступ к файловым серверам через SMB.

Аналитик L1 составляет тикет с перечислением идентификаторов событий, временных меток, вовлечённых учётных записей и IP-адресов, после чего передаёт его в группу реагирования. Ожидаемый вывод: демонстрация методики выявления цепочки латерального движения, использующего все три протокола, и отработка процедуры эскалации инцидента SOC L1.
